## Implemented scope

The sequence editor now offers **Check contact field**. It evaluates the literal current stored contact value with `has_value`, `equals` or `not_equals`. Authoring, frozen-graph inspection, offline preview and the worker share one versioned contract and evaluator. This is the stored-field part of F7; the rest of F7 remains open.

Implementation: [shared field contract](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/field_conditions.py), [atomic decision and receipt](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/sequence_conditions.py), and [full roadmap](/Users/shubham/Documents/Workspace/SocialEntangler/app/docs/OUTREACH_DRIPIFY_EIGHT_VIDEO_IMPLEMENTATION_PLAN.md).

Every configuration requires integer `condition_contract_version: 1`, an allowed `field` and an `operator`. Comparisons additionally require `value_type` (`text`, `number`, `boolean`) and a value of exactly that type. Unsupported or extra settings are rejected. Existing unversioned/unsupported settings are not reinterpreted: the editor requires an explicit setup and a reviewed new sequence revision. Numeric BSON `Int64` targets are inspected faithfully after MongoDB storage without rewriting the frozen snapshot.

Allowed standard fields are `first_name`, `last_name`, `company_name`, `job_title`, `location`, `country_code`, `email` and `phone`; these require text. One-level custom fields use `custom_variables.<key>`, with an exact ASCII letter/underscore initial and at most100 letters, digits or underscores. No nested paths, private identity/permission fields, expressions or renderer fallbacks are evaluated. Existing CSV custom values remain text; arbitrary old CSV headers need explicit mapping, which this slice does not implement.

## Value and preview semantics

For presence, missing, null, empty text and text containing only the evaluator's explicit Unicode White_Space set are absent, with distinct reason codes. Numeric0 and booleanfalse are present. Unsupported containers, non-JSON BSON scalars, nonfinite numbers, out-of-range numbers and malformed custom-field containers are unknown. Numbers are finite and within ±(2^53−1); text is bounded to1,000 Unicode characters. BSON `Int64` represents numbers within the same range. Fixed fields with nontext values require review.

Comparisons never parse CSV strings, coerce booleans to numbers, normalize case, trim comparison text or substitute generic names. Missing/null values and type mismatches are unknown, including for `not_equals`; explicit empty text can be compared to empty text. Text equality includes case and spaces. A positive email-presence condition supplies no usable-email permission, and a custom flag supplies no connection evidence. Static path analysis and subsequent physical action prerequisites retain their existing checks.

Preview field samples are separate from message-template variables and provider observation assumptions. Users choose Missing, Null, Text, Number or True/false as applicable; there is no hand-entered Yes/No override for a stored-field decision. The full typed input remains bound to the preview request digest. Incomplete or unsafe Number edits block the request rather than becoming text. Sample changes invalidate pending reports. Literal `__proto__` and `constructor` custom keys remain own properties. Decimal keystrokes and inverted/one-sided visual branch meanings are preserved. Preview sends nothing, reads no real contacts and grants no execution authority.

## Atomic worker decision and recovery

The new `data` capability channel avoids LinkedIn cookie/proxy preparation for an ordinary stored-field condition, including launch/readiness. It still requires an enabled sequence dispatcher route, current paid access, an active assigned sender, frozen sequence/campaign authorization, an explicit current `sequence` execution permission, restore-epoch admission, schedule and workspace/reply/DNC checks. It does not acquire transport ownership, create an action intent, consume a physical request budget or issue a grant. An applicable existing F6 recheck may still perform its separately guarded connection read; an entire F6-scoped job is not claimed to be network-free.

New jobs bind an exact integer contract marker, explicit nonlegacy enrollment, scalar IDs/revisions/generation, four original BSON-native identities and the deterministic workspace/stamp job key. Unstamped/copied/malformed jobs and replacement parents cannot silently gain branch authority. Older missing/legacy-derived enrollments are not automatically migrated or adopted.

The worker takes the existing workspace suppression guard and a snapshot/majority transaction. It fences current mutable authorities, evaluates the current field after retries, and commits lead advancement or a review hold together with completion and a metadata-only decision receipt in the existing sequence job. The final callback checks feature state, deadlines, epoch and schedule both before writes and after the last awaited write. This is a pre-commit callback check, not a promise that wall-clock permission cannot expire while the database acknowledges the commit. Every later action still performs its own current execution checks.

Receipts retain node references, decision/reason codes and original decision/due timestamps; they copy neither the actual field value nor the comparison target. User-chosen reference labels can themselves contain personal information; this is not an anonymous-data claim. Existing job erasure/retention controls apply, with no new collection, TTL or production index migration. Enabled-dispatcher redelivery reuses a valid completed receipt without reevaluating the contact or resetting its delay. Receipt recovery never resumes stopped work. Unknown values or malformed recipient identity data produce a durable `waiting_trigger` review hold with no due time and no automatic retry/reset path; explicit review and stopped-work remediation remain necessary.

F6 original saved-positive acceptance outranks a pending exclusive negative-path field decision in the same transaction. Only exact native-bound unsubmitted condition jobs may be superseded. The returning worker preserves superseded status; failures roll back all prepared changes from a nested redirect or field decision. This does not reopen shared joins, terminal paths, accepted/unknown operations or unsupported legacy transports.
