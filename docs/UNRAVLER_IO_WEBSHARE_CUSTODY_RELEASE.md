# Webshare application-key custody and bounded inventory reads — v2.25

Updated: 2026-10-08. Status: locally implemented and verified; uncommitted and not deployed.

## Result and scope

Webshare application keys now have opt-in scoped KMS storage, a private preparation command and exact configuration checks around inventory reads. New scoped selections seal the returned proxy password for the requested workspace and exact asset/transport identity. Default legacy custody remains compatible. The paid pilot continues using operator-imported, workspace-bound IPRoyal inventory; this slice does not switch it to Webshare.

The existing selection helper reads purchased inventory. Its name retains legacy compatibility, but it performs no provider order, renewal, cancellation or credential rotation. Current provider documentation confirms the [plan list](https://apidocs.webshare.io/subscription/plan) and [proxy list](https://apidocs.webshare.io/proxy-list/list) GET endpoints, including direct mode, country filtering and configured plan identity. Authentication remains a Token header. Returned provider data is not evidence of a verified paid term, tenant ownership or permission to automate LinkedIn.

## Key and asset storage

`OUTREACH_WEBSHARE_API_KEY_ENC` and `OUTREACH_WEBSHARE_KEY_GENERATION` select the scoped application key alongside the existing custody mode/environment and pinned KMS settings. The envelope binds a reserved application scope, the Webshare resource, credential generation, `proxy_provider_key` purpose and environment. Metadata capture and the public subsystem health diagnostic never open the key or call the provider. The health mode reports storage/configuration as mock, live or unavailable; live is not a successful AWS/provider health check.

Scoped mode rejects real plaintext configuration, constructor key overrides, missing envelope/generation/environment, wrong purpose/provider and mixed or downgraded storage. There is no mock/plaintext/Fernet fallback. Legacy mode retains explicit legacy-key callers and the old mock test path, and rejects scoped configuration. Key opening occurs outside Mongo in one bounded inventory operation; scoped application key material is not cached in the manager or queued in broker payloads. Legacy explicit callers retain their existing in-process override. Prepared values hide their key and storage in representations, bind the exact value digest, and compare the complete named mode/environment/provider/KMS policy before network use.

The initial custody observation must match the captured key policy. A legacy-to-scoped transition before capture denies before key opening/HTTP; a scoped-to-mock transition cannot return legacy mock material. The captured policy chooses tenant validation and password sealing. This closes the reviewed race where a stale initial mode could otherwise choose Fernet after a scoped key opened successfully.

Scoped selection requires a bounded workspace reference before KMS or HTTP. Returned credentials must identify one public static IPv4 asset with bounded username/password, valid port, matching country and provider inventory identity. Passwords are sealed through the existing proxy custody envelope, binding workspace, resource, generation and transport metadata. Scoped selection never creates a temporary Fernet password. Final source/deadline checks after sealing and client cleanup deny a replacement or policy transition instead of returning an asset. Proxy model representations hide password ciphertext as well as plaintext.

Sealing a selection does not reserve an IP, establish tenant ownership, verify provider expiry or authorize sender installation. This helper has no database authority or lifecycle grant; a future caller must supply the existing guarded ownership/paid-term/lease protocol. Managed Webshare import, lease integration and existing-asset migration remain separate work. Ambiguous old assets and other workspaces' leases are not silently adopted or rewritten. The old direct environment IPRoyal helper is denied in scoped mode; the existing managed IPRoyal path remains the supported pilot path.

## Bounded transport and local preparation

Inventory reads use one fixed HTTPS host and two fixed GET paths. A configured plan ID, direct mode and a two-letter country are the only proxy-list inputs. Provider `next` URLs never receive a request or key; pagination advances only the fixed endpoint. Eligible plans remain active dedicated ISP plans with automatic refresh disabled.

Each operation has a 30-second authorization deadline including key opening, inventory work and asset sealing; each paginated list call permits at most 20 pages, and all plan/proxy reads together consume at most 40 in-memory requests. A page has at most 100 records and one MiB of response bytes. Streamed bytes are bounded even without a Content-Length. Encoded, redirected, malformed, oversized or API-error responses deny with sanitized errors. There is no automatic request retry, persistent integration budget or durable inventory outcome journal in this slice. The allowance resets on a separately invoked helper operation.

The existing safe transport resolves DNS asynchronously, rejects restricted addresses and pins TCP to a validated public address. Environment proxies and redirects are disabled. Source/deadline checks run after DNS and before socket/TLS writes, after awaited client entry/exit, on headers and each response chunk, between pages and after password sealing. A changed key cannot continue with an older prepared value. SDK/cancellation cleanup and Python secret copies still need actual fleet drain; the deadline is an authorization bound, not proof that every underlying thread or socket finishes exactly at that wall-clock time. Process-local checks do not provide global cutover ordering or revoke already transmitted reads.

`python -m outreach.ops.webshare_key_secret` accepts generation/output references and hidden prompt or explicit bounded stdin input. It has no raw-key argument and no fallback to an echoing terminal. The shared exclusive, inode-fenced writer creates a new mode-0600 envelope file and refuses existing files/symlinks. The command installs no configuration, changes no database, grants no permission and contacts no Webshare endpoint. An explicit operator invocation with scoped custody uses the existing KMS adapter; local tests substitute the key service. Errors and accidental key arguments are sanitized. Token-header, Webshare environment-field and named-log-argument redaction are verified.

The shared deployment environment maps the envelope/generation pair once for API and worker services. Production Compose is a symlink to the development file; the review caught and removed the initial duplicate mapping before validation. Empty defaults preserve the current deployment mode and enable no operation.
