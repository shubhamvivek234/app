## Read contract

The new GET `/sequences/templates/{template_id}/revision-checkpoints/{checkpoint_id}/content` requires exactly one `identity_digest` and `history_digest` query value. The explicit original native identity survives public-ID replacement and source deletion; references locate data and do not confer access. Unknown query keys and duplicate or malformed references return422. Well-formed unknown checkpoints or native history identities return404. Current workspace readers (owner/admin/editor/viewer/client under existing sequence:read policy) may inspect retained content; creator attribution is not an access override. Authentication precedes the handler, and the same owning transaction rechecks current native user/UID uniqueness, active role/member-or-owner identity, workspace/identity erasure and shared authority counters.

Only an explicit ordinary checkpoint can supply content; selecting a deletion terminal holds409. A valid selected pair can be returned with terminal_recorded=true after source deletion or replacement, without inspecting or modifying the replacement.

Both metadata and graph snapshots must pass their unchanged strict codec, canonical typed/context/ID/checkpoint binding and key checks. Both absent returns404; one absent, duplicate/aliased/oversized/corrupt/transplanted candidates or stale lineage/reference holds409. Missing key/storage/index prerequisites and unconfirmed commit return sanitized503 without content. The wrong usable key holds409. Successful response fields are allowlisted metadata name/description, graph nodes/edges/tree, explicit public/native/checkpoint/history digests, revision/event, separate per-kind original capture attribution/time and false capture_complete/restore_available/execution_authorized flags. It returns no ciphertext, Firebase UID, source private extras or compiled graph. Separate capture audits do not claim the two rows were originally captured atomically.

Content is released only after a confirmed owning commit and a final read-setting check. Successful reads write the existing guard/user/role authority counters. Failures before commit roll back transactional authority writes; an unknown commit acknowledgement or disable observed after commit can leave those counters committed while still returning no content. Normal authentication hydration can also write outside this transaction. There is no replay, receipt recovery or execution grant from a content GET. Retrying is an explicit fresh read with current access checks. Conflicting role/UID revocations committed after snapshot start but before the read's authority fence force conflict/retry and denial; a change ordered after the read need not prevent it. A read ordered before an erasure stop can complete, while later reads deny. This does not revoke responses already issued or globally fence raw writers.
