## Visible behavior

The sequence editor has **Validate & preview sequence**. Review accepts supplied sample fields, custom text variables, an initial connection/usable-email assumption and per-condition observations. Unknown is the default. Successful action completion is an explicit, initially disabled assumption. The preview makes no provider request, reads no real contact and creates no task, permission or execution grant. Existing authentication, resolved workspace/role and erasure admission still run; the preview handler itself is a supplied-data calculation.

The result shows graph findings, the illustrated steps, rendered copy, configured delays and separately assumed deadline waits. Message previews show at most 2,000 characters per field and disclose truncation; execution rendering is bounded to 10,000 characters. Custom missing variables stop the illustrated path and are named. Existing built-in generic/empty fallbacks remain, with a review warning; the displayed copy is illustrative, not a review of every enrolled contact. Variable values are substituted once and cannot recursively expand other values. Actual recipient/context rendering, content review, budgets, source/custody and scheduling checks remain required.

A request UUID and complete input digest bind the submitted graph/tree/sample/assumptions; a separate digest identifies the compiled graph. The current actor/resolved workspace must match a server-issued scope digest. These are response/context correlation, not signed authorization or provider evidence. The browser clears results on edits, campaign/tree changes and closure, cancels pending requests and rejects stale/malformed/authority-claiming responses. Preview stays disabled while an existing campaign graph loads. Failed/missing/incompatible saved visual graphs show a load/review error instead of the editor's local default.

Hour-only historical trees display their actual delays. Delay editing stores exact integer hours and removes obsolete day fields. One-sided branches display an absent outcome as terminal without fake Add controls; recursive edits preserve absent branch keys. Hidden nested linear `step.steps` actions are rejected because this editor cannot display/edit them faithfully. Empty lists remain harmless; no migration or hidden-action conversion is attempted.

## Shared graph and path contract

New campaign and custom-template saves use the same compiler/analysis as preview and launch readiness. Existing immutable campaign sequence versions and conditional pointer publication remain in use; previous snapshots are never rewritten by validation. New saves mark compiler contract version 1.

The contract bounds graphs to 100 nodes/200 edges and finite JSON to 1 MB, 20,000 traversal items and depth 12 before recursive analysis or hashing. Depth is JSON container depth, not twelve nested visual branches. Pending traversal allocation is bounded before enqueuing a wide container. IDs are scalar ASCII identifiers of 1–200 characters; configs are objects, titles bounded text, delays integer hours 0–8,760 and condition deadlines integer days 1–30. Day values must resolve exactly to whole hours, with no rounding/coercion. Consumed recent-post age is an integer 1–365 days and skip-if-no-posts is a strict boolean. JSON integers fit BSON signed64 and object keys exclude NUL. These are application validation bounds, not an HTTP ingress/body-memory or arbitrary database-byte bound.

Branch names belong to their source action/condition. Misspellings, cross-condition vocabulary, conflicting source handles/display labels, multiple targets for one outcome and competing default/conditional successors are rejected. Cycles, missing targets, multiple roots and duplicate identities remain errors. Unsupported node topology may be inspected structurally, but semantic validation blocks unsupported runners and unfinished AI-prompt markers independently of live feature flags.

Path analysis keeps connection and usable-email states across merges instead of accepting a path because another predecessor is safe. Known negative/invited paths cannot message without a positive connection check; a negative email path needs new usable-email evidence or a finder/check path. An invitation does not establish connection. Already-invited paths cannot request another invitation, including after a negative wait observation. Positive reply successor work is invalid because recorded replies stop outreach. Unknown initial state is a runtime requirement/warning, not invented negative evidence. Analysis uses at most twelve connection/email states per node, capped findings and bounded witness suffixes; truncated witnesses are disclosed. It is not an all-runtime-authority model.

Template GET adds read-only compatibility findings without rewriting old template documents. The campaign template table displays failed compatibility and uses the server graph instead of silently substituting another local graph. Broad template governance, ranking and statistics remain F12. The existing template Use allowlist remains LinkedIn-only; backend-compatible email templates can still be unavailable in that gallery.

## Timing and submission behavior

Preview distinguishes unknown, observed negative before a deadline, assumed negative at a deadline and unknown at a deadline. Before-deadline negatives wait; unknown at the deadline requires review rather than becoming a negative branch. A supplied email address never establishes usable-email permission. Positive recorded replies stop; no successful action/provider outcome is inferred. A terminal connection condition with no outgoing paths is explicitly terminal, matching the existing runner without promising an observation. Working hours, rate limits, queue latency and current authority can defer actual work beyond the illustrated delays.

The worker now applies each saved successor delay on connection/reply and email-availability branches as well as ordinary successors. A missing branch safely finishes. Launch/intake initialize a new root at the later of launch/admission time and warm-up completion, plus its saved delay. Existing initialized due times are retained subject to the warm-up floor; launch does not restart condition waits. Malformed active-intake graph/warm-up authority rolls back admission. Active workers require an initialized scalar current node; missing/unknown/malformed nodes hold instead of falling back to root or fabricating completion.

Future due times stop before preparation and are checked again at final submission. Frozen graph structure/source consistency is checked before custody/provider setup and again at final submission; invalid older data returns a review hold without clearing original task evidence. Rendered unresolved variables hold final submission. Present wait starts require a native datetime (BSON-naive values mean UTC) or strict timezone-qualified ISO datetime; malformed, future and UTC-overflow values hold instead of inventing a new start. A negative reply branch requires the existing completed inbox freshness check. Stale/unknown inbox state waits or requires review at the deadline; a recorded reply stops immediately before provider preparation.

Compiled-only historical graphs may be inspected without reconstructing original source fidelity: implicit map-key node IDs and explicit null terminal outcomes are recognized. Missing historical root delay means zero; missing successor delay retains the old 24-hour default. These inspection defaults never rewrite snapshots. If original source is present but disagrees with the frozen graph, new work holds. Existing graphs lacking a faithful visual tree remain unavailable for editing until a separate reviewed migration; this slice does not adopt or reinterpret them. Existing data-only receipt recovery, uncertainty holds and human/provider evidence remain intact; no automatic resend, campaign resume or approval renewal is introduced.
