Updated: 2026-10-16 IST. Bounded F5/F12 compatibility correction, local and uncommitted/undeployed. Follows [inbox organization](UNRAVLER_IO_INBOX_ORGANIZATION_RELEASE.md) and the [eight-video roadmap](OUTREACH_DRIPIFY_EIGHT_VIDEO_IMPLEMENTATION_PLAN.md).

## Behavior and authority

The gallery previously rejected backend-compatible email templates using a separate LinkedIn-only allowlist. It also showed local starters while catalog loading failed or returned empty, and could substitute a local graph for an incomplete saved template by ID/name. The gallery now uses the received server graph and strict contract1 compatibility: valid=true, configuration_available=true and execution_authorized=false. Shared server graph/capability analysis checks supported runners and matching visual-tree fidelity; configuration availability additionally requires a nonempty editable tree. This supports existing email, finder, usable-email and stored-field steps independently of live flags. It adds no new starter template, runner or observation source.

The browser checks bounded nodes/edges/tree shape, raw node identities, edge endpoints and the existing editor's visual-tree flattening. It does not recreate complete compiler/path semantics or attest complete graph/content equivalence; server save remains authoritative. The existing exported isLaunchableTemplate helper now means configuration eligibility only. Visible readiness says Ready to configure. Sender/mailbox selection, entitlement, consent/content approval, suppression, freshness, physical email policy and actual launch/worker controls remain separate.

Missing user/database or failed custom-template reads return a sanitized503 rather than a successful starter-only catalog. GET removes native _id from response copies without mutating received source dictionaries. Existing workspace filtering/sorting and100-row custom-template cap remain; this is not a complete-history catalog or a new transactional admission protocol. Stored malformed graph findings stay review-only. The browser rejects malformed catalog envelopes/display fields and duplicate IDs, shows explicit Retry for failures and a truthful empty state. It never substitutes local starters on these paths.

Catalog request generations ignore late results after close/reopen or unmount. A component-local single-flight latch blocks overlapping Use. Mount/generation checks stop dependent sequence saving/navigation after departure. Known successful Use copies the exact received graph into the existing auto-draft then sequence-save endpoints; it never launches. These are two separate requests: unknown network acknowledgement, browser reload or cancellation may leave a draft or saved sequence, and a later manual retry may create another draft. Durable operation receipts/idempotency and cleanup/recovery are not supplied by this slice. A request already accepted before unmount cannot be recalled.

Existing authentication resolves the active workspace and checks its role/open state. After original membership revocation it may select/create a personal workspace; a200 response does not prove continued access to the original workspace. Native checks verify that the original templates are excluded and a stopped resolved workspace is denied. No new continuous role fence, exact-byte snapshot/completeness claim or new template mutation authority is made. Current custom-template POST/DELETE remain unchanged and need separate scoped governance, including native/revision identity, current authority/erasure ordering, retries and unknown mutation outcomes. No immutable template history, sharing/team ownership, sender ownership, ranking or conversion metrics are added.
