# Unravler.io v2.57 — activity-stream access revalidation

Date: 12 October 2026 (IST). Local work on `main`, based on `3fc64f70cea68dbaf19aefaf349020d5c9c789a3`. This change and the preceding v2.56 repair are uncommitted and undeployed. The last recorded production application release remains v2.55 at `b85b2df`; this work does not reverify production.

The P1 access-lifetime portion of audit A15 is repaired locally. An open activity producer previously retained its initial workspace access after membership removal. It now checks the captured actor and original workspace before reading tasks and before emitting each task or heartbeat. Revocation or failed authority reads stop further activity. The Home page closes the connection and clears cached activity when the server reports an access stop. **A15's P2 delivery/completeness defects remain open, so 17 audit finding groups still contain unfinished work.**

## Behavior and boundaries

- [The stream authority](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/activity_stream.py) captures scalar user ID, workspace ID and optional Firebase UID. Current primary/majority reads verify the same user/identity mapping, non-deleted user, identity tombstone, existing scalar workspace, valid scalar membership/role or exact scalar owner, and workspace deletion guard. It never selects a replacement workspace, creates membership or changes access authorities. An array alias cannot satisfy the intended scalar authority.
- [The route](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/api/analytics.py) retains normal cookie authentication and v2.56 request admission. It starts a 300-second monotonic generator deadline when constructing the response. The producer checks the deadline before and after awaited authority reads, before task queries and between already-materialized task rows. Authority checks and task reads each have a maximum five-second await budget, reduced by the remaining lifetime. Idle polls occur every 15 seconds. Cancellation propagates normally.
- Access changes, unavailable reads or unusable database configuration produce a sanitized `stream_closed` control and then end the generator. Its only fields are the control type and a generic `access_changed` or `unavailable` reason. No actor, workspace, task, credential or exception detail is included. Ordinary lifetime expiry ends with EOF; native EventSource may reconnect through normal request authentication.
- [Home](/Users/shubham/Documents/Workspace/SocialEntangler/app/frontend/src/outreach/pages/OutreachHome.js) ignores queued activity after a terminal stop, closes EventSource, clears cached events and shows “Activity unavailable” with “Refresh to check access again.” Transport errors also clear cached activity and suspend acceptance until a fresh `connected` greeting. Normal reconnect is preserved. This is a frontend behavior change, without a layout redesign.
- Task queries remain strictly bound to the original workspace. Existing newest-ten/time-window selection and completed-task semantics are preserved. Aggregate/export analytics remain compatible; they still require their shared `json` and `asyncio` imports.

These are sequential majority observations, not a transaction ordering revocation with sending. A revocation can occur after the final check and before network emission; already-sent or buffered bytes cannot be recalled. The 300-second deadline bounds generator admission/emission checks, **not unconditional socket closure under a blocked ASGI send or proxy buffering**. The 15-second poll and read budgets are not an instantaneous revocation promise. Continuous Firebase global-token/Redis-blocklist revocation is not added; ordinary new connections reauthenticate, and the generator has its finite deadline.

Repeated authority reads add database load: roughly 11 authority/task reads per empty steady-state poll and 61 per ten-task poll, excluding the initial greeting checks. No concurrency/load or production performance certification is claimed. The current feed can still lose bursts above ten completions, replay recent tasks on reconnect and omit activity outside completed tasks. Durable IDs/cursors, chronological draining, resume/deduplication and truthful event coverage require the separate P2 repair. A heartbeat remains connection activity, not campaign health.
