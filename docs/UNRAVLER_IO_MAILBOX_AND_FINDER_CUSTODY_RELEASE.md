# Unravler.io — mailbox, OAuth and finder credential custody
Version: 2.14.0 | Updated: 2026-10-04 | Status: Local implementation; deployment and AWS verification pending

The thirteenth slice adds opt-in scoped custody for installed Gmail/Microsoft tokens, pending OAuth code/PKCE material and workspace Hunter keys. It also makes refresh uncertainty durable and supplies private drained conversion of existing installed credentials. Default custody remains `legacy_fernet`; live actions and campaign voice generation retain disabled defaults. No commit, push, deployment, real AWS/key-service/provider call, production grant or purchase was made.

## Implemented scope

- Mailbox access and refresh values use separate KMS/AES-GCM purposes. Authenticated context binds workspace, sender, provider/user/email/connection identity, a connection custody generation and environment. Successful refresh retains that identity/generation; reconnect receives a new custody generation. Hunter keys bind workspace, canonical Hunter resource, credential generation, purpose and environment. Sender authorization remains a separate authority because the key is shared by the workspace.
- Pending OAuth code and PKCE values bind workspace, sender, provider and job identity with separate purposes. Browser-bound single-use state and job consumption commit together under the workspace guard. Start checks paid/transaction/workspace capability before key work and repeats current authorization at insertion. Worker exchange checks exact running-job owner and captured encrypted material after opening, current pilot/shutdown controls and the original authorization deadline. Profile reads and token installation repeat owner/control checks. Job-owned installation cleanup includes the installed custody generation and preserves replacement credentials.
- KMS mode rejects plaintext, mock/unscoped Fernet values, missing context, cross-purpose/context swaps and downgrade. It reuses the pinned temporary workload-role/key-ARN contract and bounded SDK from the [custody foundation](UNRAVLER_IO_CREDENTIAL_CUSTODY_RELEASE.md). OAuth application client secrets in environment configuration remain outside this conversion.
- Email/finder adapters prepare operation-local values before final dispatch authorization. Pure comparisons bind actual bearer/key values to the same captured encrypted material across key-service awaits, including current mode/environment. Final authorization uses the existing transactional sender/approval/resource/receipt boundary; no key work occurs inside its retry callbacks. Mailbox token expiry is included in the captured post-commit deadline set. No process-wide secret cache is introduced; Python memory zeroization is not established.
- Scoped mailbox sync reads require a prepared access object and database-only current mailbox/token/paid/pilot preflight immediately before each provider GET. This adds credential authorization, not a full durable sync HTTP outbox or physical budget/receipt protocol. Older/raw writers and already-authorized transport still require operational drain.
- Refresh claims exact connection/token material with a nonce, then commits a `possible` marker under the workspace guard before OAuth HTTP. Expired leases cannot reclaim `possible` or `unknown` outcomes. Cancellation, lost permit acknowledgement, timeout, malformed response and post-response key-service failure retain a durable hold and old encrypted evidence. Subsequent refresh cannot replay the request. Explicit provider rejection disables/scrubs local tokens; guarded reconnect can replace a hold, and clears obsolete refresh markers.
- A usable response is resealed outside transactions and installed only under the exact current owner/material/paid/control fences. Rotated or retained refresh values remain purpose-bound. A lost installation acknowledgement cannot scrub or overwrite committed replacement ciphertext. BSON UTC millisecond normalization prevents a successful stored expiry from failing its own exact readback comparison.
- New Hunter key writes are scoped and workspace-guard ordered, with a transaction/erasure preflight before key work. Delete participates in the same ordering. Shared emitted-handler scrubbing now redacts short and percent-encoded credential-bearing query strings and URL arguments; the actual Hunter/httpx logging path is covered. This is local logging evidence, not a claim about remote provider or infrastructure logs.
- Private mailbox/finder conversion requires disabled live actions, `kms_v1` in the isolated operator process, identified operator, exact inspection digest and explicit drain of all credential writers. All workspace senders must be stopped with idle, latched execution; the pilot is bounded to five sender/mailbox rows, with unknown/capacity gaps denied. Pending OAuth states/jobs, held refresh/sync ownership, active campaigns/connections and unresolved physical/provider work deny conversion. Only strictly decryptable legacy values with current explicit workspace ownership are accepted.
- Conversion performs key work outside guard callbacks, then rechecks the complete captured authority snapshot. Credentials and a TTL-free metadata receipt commit together. Mailbox connection identity, cursor, status, cookie generation, leases and stopped execution are preserved. A completed receipt retry reads metadata/current ciphertext identity without reopening or resealing values. Existing billable lookup/action deduplication remains authoritative. Erasure scrubs these existing secret fields and includes migration receipts in ordinary tenant purge. Possible/unknown refresh outcomes retain only minimal operation/state/hash evidence without mailbox addresses, tokens or lease nonces; denied callbacks preserve unconsumed scrubbed state for drained purge.

## Private operator procedure

Keep live flags disabled. Drain old/new API, mailbox OAuth/refresh/sync, email/finder transports, integration, media, publishers/recovery and other credential writers and their caches. The CLI string is an operator assertion, not proof that those processes stopped. Verify replica-set transactions and actual indexes first. Real standalone MongoDB denies conversion and Hunter key insertion before key-service work.

Configure the same verified KMS workload contract in the isolated operator process. Enabling KMS mode on live services before compatible LinkedIn, proxy, mailbox and finder material has migrated causes denial. Existing pending OAuth material is not adopted by this conversion: finish/cancel and drain that lifecycle or reconnect after cutover; stale/held records require separate review.

```bash
.venv/bin/python -m outreach.ops.pilot inspect-provider-custody \
  --workspace WORKSPACE --kind mailbox --sender SENDER
.venv/bin/python -m outreach.ops.pilot migrate-provider-custody \
  --workspace WORKSPACE --kind mailbox --sender SENDER --operator OPERATOR \
  --review-digest INSPECTION_DIGEST \
  --workers-drained I_PAUSED_AND_DRAINED_ALL_CREDENTIAL_WRITERS
```

For Hunter, use `--kind finder` and omit `--sender`; every workspace sender remains part of the stopped inspection. Commands return identifiers, blockers, digests and completion metadata, never keys, tokens or ciphertext. Retry a completed operation with its original review digest; replacement material is reported rather than adopted. Migration never resumes campaigns, grants permission or calls providers.

The frontend is unchanged, so the prior 88 tests and production build are retained rather than claimed as newly rerun.

The clean final main run passes all 1,120 checks (1,100 outreach plus 20 account/auth companions). Its 44 skipped drills pass separately, giving 1,144 distinct outreach checks and 1,164 total backend checks.
