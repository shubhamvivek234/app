## User behavior

The Templates gallery offers **Edit template details** for a supported custom template with dedicated native review metadata. A user can rename it and change or explicitly clear its description. Workspace editors and administrators use existing `sequence:update` permission; current unique owners retain the existing owner fallback. This is shared workspace metadata, with no creator-only override or new sharing model. Prebuilt templates and missing/unsupported reviews keep editing unavailable.

Only `name`, `description`, `template_revision`, `metadata_updated_at` and `metadata_updated_by` change. Original native/public/workspace/creator identity, graphs, visual trees, compiled content, creation timestamps, unknown fields and independent campaign/version/task/lead copies remain intact. Metadata editing does not repair an incompatible sequence, recompile it, publish a campaign version, launch work or authorize execution. Template names need not be unique.

## Server contract and ordering

Gallery GET adds `metadata_review`, computed from the original received BSON row before projection. Its full-record and native identity digests use the established review encoder; a distinct `template-metadata-scope-v1` digest binds the original actor, authenticated UID and resolved workspace. Metadata and deletion proofs cannot substitute for each other. Pure review grants no update or execution authority.

`PATCH /sequences/templates/{id}/metadata-reviewed` accepts only exact version/workspace/revision/digests plus required name and description. Strict HTTP fields reject coercion, unknown fields, graph/source changes and client-supplied audit/result fields. Direct service entry validates scalar proofs too. Names require nonblank text of at most100 Unicode code points; descriptions allow0–1000. NUL and invalid Unicode surrogates deny. Exact accepted text is retained without normalization. The browser conservatively applies these numeric limits in UTF-16 code units. Unsupported existing metadata stays review-only, including stored null descriptions; an absent description is compatible with empty text.

One shared workspace guard/snapshot/majority transaction captures and rechecks the current unique native user for the original actor/UID, current member role or unique owner, active/open workspace and identity-erasure tombstone. Native user/authority counter writes fence concurrent role/user changes. A bounded scoped lookup rejects duplicate scalar public identities and compares captured template native identity, revision and full-record fingerprint. A copied `$literal` full-row CAS replaces only that original native template row with the preserved original plus five metadata fields. Exact BSON readback must match the prepared replacement before a receipt commits. Mongo object equality alone is not strict BSON-byte equality; transactional reread/fingerprint and write conflicts supply the tested protection.

Revision absence is legacy0. A successful accepted edit increments once, including unchanged text. The maximum stored revision is JavaScript's safe integer ceiling; the final increment may reach that ceiling, after which editing stays unavailable. A UTC millisecond timestamp and admitted public actor ID record the latest edit, replacing previous metadata audit fields. This is current audit metadata, not immutable history or proof of all previous edits.

The established1MB full-BSON bound applies after loading/encoding original and prepared rows, rather than a strict ingress/read memory bound. No collection, index, receipt journal, provider job, execution grant or production migration is added. Original v2.76 creation receipts remain historical: after editing, identical original save replay/status returns the original revision1 receipt without recompiling, overwriting newer content or creating another template. Actual guarded erasure still removes the entire template and metadata.

## Browser and uncertain outcomes

Opening the editor synchronously excludes gallery Use/Delete/edit and catalog replacement. Save captures exact review/text and token before one PATCH; inputs freeze while pending. Confirmation requires HTTP200, exact original native/context/revision/text fields, exactly the next safe revision and a valid new full-record digest, with no invented fields. Mount/original-prop/token checks fence late results. Confirmed success closes the editor and fetches the catalog rather than reusing stale deletion/use reviews; a failed catalog read exposes Retry with no stale actions.

Network errors, stale403/409/404, malformed JSON, mismatched receipts and other status codes stay unconfirmed. Save and Cancel remain held. **Reload and review templates** is explicit, synchronously single-flight, GET-only, requires HTTP200 and rechecks the captured token after JSON before installing results or releasing the hold. Failed/rejected/changed-account refresh stays held. Successful refresh closes the old editor and shows an unconfirmed-update notice; it does not claim the old request succeeded. A new edit requires deliberately reopening a currently reviewed row. No PATCH is automatically replayed.

Edit drafts/holds and the notice are memory-only. Full unmount/reload loses this edit UI state; there is no durable edit outcome receipt, recoverable request ID, cancellation protocol or cross-tab lock. Existing same-tab creation references remain unchanged. Catalog100-row limits, sequential read/current-role limits, raw/older-writer/global uniqueness, post-commit account changes and backup/source completeness limits remain. Old template writers must drain before coherent rollout; new checks cannot fence an already-running old binary.
