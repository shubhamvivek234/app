# Unravler.io v2.39 — selected invoice reuse exclusions

Date: 2026-10-09. Local, uncommitted and undeployed. Foundations through v2.22 remain at `04ca28b5d1dd7bd213ea67e951970e19fd93bdf3`; earlier local changes remain intact.

## Result and limits

A private controller can restore selected global invoice-binding digests lost by an older backup as permanent reuse exclusions. It creates no payment receipt, entitlement, owner, provider asset, term, consent, credential, grant or campaign resume. Payment finalization now participates in the existing workspace guard/snapshot/majority transaction and positive execution-epoch admission; a stopped restored epoch cannot finalize paid access. Global invoice-row write fences serialize participating imports/payments even when workspace guards differ.

Original invoice guards are reserved before receipt/entitlement writes. A guard may therefore represent an interrupted reservation: it is not proof that payment occurred, an invoice was consumed, or a person/workspace owns an invoice. Import conservatively blocks reuse pending separate reconciliation. The requested workspace binds review/epoch/journal scope, not ownership of the global hash. Raw invoice IDs, bound workspace, seats, paid-through terms and payment dates cannot be reconstructed from this manifest.

This is selected negative reconciliation, not complete or authenticated recovery. Individual majority reads and an asserted all-writer/cache drain do not prove one atomic source snapshot. The exact byte digest protects reviewed integrity, not origin or trust. Source provenance, complete selection and private storage outside backups remain operator responsibilities. Restored negative facts do not authorize activation.

## Selected source and private artifact

Export accepts 1–100 distinct canonical SHA-256 global `account_invoice_guards._id` references and requires a source drain assertion. Every selected original row must have its original canonical binding digest and no `restore_reuse_blocked` field. Missing, malformed or already imported/blocked rows deny. No tenant invoice listing, implicit expansion or raw invoice lookup is offered.

The strict version-1 manifest contains only `workspace_guard_digest` and invoice/binding digest pairs, with a 65,536-byte limit. Duplicate/unknown fields, boolean/unsupported versions, duplicate references, malformed UTF-8, nonfinite values and capacity excess deny. Immutable sorted facts, exact-byte source digest and normalized-fact digest bind review. No payment status, receipt, raw invoice ID, customer identity, seats, term or timestamp is inferred.

The CLI reuses v2.36 private file helpers unchanged: exclusive 0600 export in an owned private directory, bounded stdin or owned private regular input, no overwrite/symlink/hardlink and changed-read denial, with inode-owned partial cleanup. Input is read before connecting to the database. Console output is bounded metadata, counts/digests and the requested workspace ID; argument/runtime failures are sanitized. It does not echo manifest contents or raw invoice material. This does not claim additional privacy/error hardening of the older payment CLI.

## Stopped import, retention and payment ordering

Inspect/apply require the matching prepared stopped v2.35 root and all five execution/health flags false. Apply also requires exact source/operator/evidence/review digests and an all-writer/cache drain assertion. Because only permanent hash negatives are installed, an already-closed target is allowed only with that matching root still present; closure is never cleared. Full erasure removes the root and journal, so later import cannot bypass ordinary preparation or reopen a tenant.

The existing guard/snapshot/majority transaction fences root/guard/journal. Selected global invoice rows use the same raw Mongo session and explicit write fences. Existing bindings must exactly match; malformed reuse flags deny. Missing rows receive the original binding with setOnInsert, then each selected row receives `restore_reuse_blocked=true`. Readback proves all blocks before a permanent hashed source journal is written. Saved retries require original review hashes, current root and every block still present. Concurrent/lost-ack retries cannot overwrite replacements or use a journal to hide missing authority. Observed final policy/flag changes roll back; commit can follow the last local check. Raw/older writers, caches and fleet/kernel enforcement remain outside this protocol.

Retention-first TTL removal covers the new journal and permanent global invoice guards. A strict unique `(workspace_id, execution_epoch, source_digest)` journal index precedes cutover; the existing global `_id` identity remains unique. Erasure purges the workspace journal and retains minimal hashed provenance; global invoice exclusions remain outside tenant purge and have no TTL or reopening path supplied. No network, provider or key operation occurs.

`record_verified_payment` captures epoch policy before preparation and finalizes under the existing shared transaction. It revalidates/read-fences the exact current access request, entitlement and original receipt, and claims the global binding in the same session. Different-workspace/different-term use, restored blocks, malformed authority, changed request, revoked new access and stopped epochs deny. New receipt/entitlement/request completion commit together. Actual paid-term deadlines are checked before and after financial writes; observed final policy/deadline failure rolls back all writes. Exact receipt retries preserve the current entitlement and do not reactivate expired/revoked status. A concurrent exact retry may observe the first transaction's fulfilled request, while request identity/country/seats must still match. Successful retries still require the existing future-term/request/capacity preflight. The private pilot CLI now reports current status and revocation rather than claiming unconditional activation.

Existing IP-capacity preparation remains outside the financial transaction. This does not establish atomic provider capacity, resolve missing payment/provider facts, authenticate external invoices or reconstruct paid access. The legacy archival binding helper can verify/preserve a blocked binding without granting anything. A negative imported after a payment already committed does not retroactively revoke access. Source/target all-writer/cache drains remain assertions.

## Private procedure

On the trusted source, independently identify original invoice-guard `_id` digests and their provenance; do not treat them as proof of payment. Drain source writers/caches. Run `python -m outreach.ops.restore_invoices export --workspace WORKSPACE --invoice-digest DIGEST --output-file PRIVATE_FILE --all-writers-and-caches-drained`, repeating `--invoice-digest` for selected hashes. Use an owned private directory and keep the artifact outside backups; the app cannot verify that storage location.

On an isolated target, keep all five flags false, drain writers/caches and prepare the matching stopped epoch. Run `python -m outreach.ops.restore_invoices inspect --workspace WORKSPACE --manifest-file PRIVATE_FILE` (or bounded `--manifest-stdin`). Review exact source/counts/digest, then apply the same source with `apply`, `--operator`, `--source-digest`, `--evidence-digest`, `--review-digest` and `--all-writers-and-caches-drained`. Retain the original digests for retries. No payment reconstruction or activation follows. Keep execution stopped pending remaining reconciliation and explicit activation design.
