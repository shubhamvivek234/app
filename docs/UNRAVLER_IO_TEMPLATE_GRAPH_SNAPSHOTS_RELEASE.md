## Graph field contract

[template_graph_content.py](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/template_graph_content.py) selects exactly `nodes`, `edges` and `tree`. It preserves accepted stored fields, absent defaults, array order and JSON numeric representations rather than rebuilding a minimal executable graph. Root source metadata, compiled output, credentials and Firebase UID fields are excluded from the copy. Unknown or malformed nested fields hold the entire capture instead of being silently removed. Allowed free text can itself contain sensitive information; field exclusion is not secret-content detection. Original source templates remain plaintext.

The version-one node policy covers IDs, supported action types, titles/subtitles, exact hour delays, typed per-action config and bounded visual positions. Tree-specific day delays, branch conditions/types/steps, empty legacy `steps`, end markers and required-action flags are validated. Edge IDs, endpoints, labels and handle strings are supported. Plain JSON/type, depth/item, finite safe-number, text, ID and byte limits apply. BSON Code, bool/number aliases in typed fields and unknown enum/config values hold. Accepted BSON `Int64` values become JSON integers in the encrypted copy; this is not a complete BSON backup. The checkpoint's full BSON digest still binds the original native representation.

Explicit configurations cover profile visits, connection requests, messages, voice scripts/fallbacks, post likes, connection conditions, email discovery, email sending, email-availability conditions and typed stored-field conditions. Existing shared compilation and visual-tree agreement must pass. A legacy record with both stored compiled fields absent can pass; when either exists, both must have the exact current compiler marker and canonical compiled result. The snapshot preserves definitions, including UI settings; it does not prove those settings execute, rendered output matches, any provider succeeds or execution is authorized. Unsupported historical definitions remain held for an explicit future contract.

## Shared current-proof capture and encryption

[template_snapshot_capture.py](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/template_snapshot_capture.py) extracts the existing metadata capture transaction into a frozen policy selected by trusted source wrappers. Request input cannot choose a collection, codec or callback. Both wrappers pass their current callbacks and limits, including their own transaction function; metadata schema, codec functions, limits and retained-row loader remain unchanged. The refactor is covered by the original metadata tests and wider template checks.

The dedicated graph scope binds current actor, authenticated UID and workspace. Inside the same owning guard/snapshot-majority transaction, capture checks update permission, strict unique native user/UID/member-or-owner authority, session identity/role/erasure/open-workspace observations, original native identity, public ID, revision and exact full-record digest. The bounded retained digest lineage must validate with an exact ordinary checkpoint at the current revision and no deletion terminal or future revision. Missing history is not reconstructed. Successful capture writes guard/user-role counters plus an immutable snapshot; it does not edit the template, increment its revision, append checkpoints, write a recoverable operation receipt or grant execution. Final JavaScript-safe revisions can be captured without incrementing.

[template_graph_snapshots.py](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/template_graph_snapshots.py) uses its own collection, ID/scope domains and `template_graph_v1` content kind. Its exact twelve-field outer envelope binds workspace/public/native identity, revision, full-record digest, matching checkpoint ID, public actor and UTC millisecond capture time. Strict Fernet decryption authenticates canonical typed context plus the selected graph. Duplicate/extra JSON keys, noncanonical payloads, context substitutions, missing/wrong keys and cross-kind transplants hold without plaintext fallback, repair or silent re-encryption. Public metadata and ciphertext lengths remain linkable. Existing key custody/rotation and backup handling remain dependencies; this adds no KMS, cryptographic erasure, WORM or authority outside database/key backups.

Every retained row must validate against its matching checkpoint. Repeating the same still-current proof preserves the original ciphertext and audit bytes and returns only a minimal metadata receipt, without graph/text/ciphertext. Canonical JSON comparison with the current graph distinguishes otherwise valid `1` from `1.0`, even though ordinary Python equality accepts them as equal. A sanitized unknown-acknowledgement response can be explicitly retried only while original current proof survives; this is not historical result recovery, backfill or automatic replay after later edits/deletion.

## Storage, retention and actual erasure

The new `outreach_template_graph_snapshots` collection uses the separately prepared nonunique ascending `(workspace_id, identity_digest, revision, _id)` index with simple collation. Only an explicit administrative helper prepares it. Capture observes both graph/history index contracts before and after work, forces the matching hint and holds on missing/conflicting definitions or any TTL index. It never creates indexes from startup/customer requests, drops/repairs indexes or evicts records. These observations are not a global DDL fence.

Graph-specific limits are 100 retained snapshots per native identity, 128KiB canonical graph UTF8, 190,000 ASCII ciphertext characters, 256KiB per stored BSON row and 8MiB accepted retained-plus-new BSON. The graph limit is independent of metadata's unchanged 1,000 rows/16KiB row/14,000-character token limits. At most 101 projected wrappers are returned with a 2,000ms aggregation, batch size25 and oversized-row size/null sentinels, including oversized native IDs. The 8MiB check follows bounded projected loading: 101 individually accepted-size rows could approach 25.25MiB before that total check. It is not an 8MiB physical transfer, server-work or whole-transaction runtime cap. Same-native malformed/public-ID-drift candidates count. Capacity allows confirmation of an existing exact snapshot but holds a new one without eviction.

Insertion requires exact BSON readback and decrypted canonical-content comparison. Insertion/readback/index-drift failures roll snapshot and authority counters back together. Actual guarded account/workspace erasure includes both metadata and graph snapshot collections, even after source deletion; erased authority cannot capture again. Old erasure workers and incompatible writers must be drained/replaced before later activation. Raw writers, whole-backup rollback, key retention and operational resource behavior remain separate limits.
