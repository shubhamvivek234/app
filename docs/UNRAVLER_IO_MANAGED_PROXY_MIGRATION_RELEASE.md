# Reviewed managed proxy custody migration — v2.28

Updated: 2026-10-08. Status: locally implemented and verified. Uncommitted and not deployed.

## Result and boundary

The private proxy migration now converts the original strict-Fernet password of a **proven v2.27 managed Webshare asset** into the existing scoped KMS/AES-GCM proxy envelope. It preserves the purchased provider term, original manual import basis, transport, proxy credential generation, permanent physical IP exclusion, sender lease/reservation identity, cookie generation and stopped execution permission. Inventory and every present matching sender proxy alias change atomically. An unused proven asset may convert without creating a lease, sender or permission.

This is storage conversion, not adoption of old Webshare helper records or vendor proof. Webshare requires the original normalized manual workspace/plan/resource/order/term/evidence basis and its permanent IP binding. An operator must supply a separate SHA-256 review-evidence reference. Missing/changed basis, claim, lease country/provider, owner, expired term, alias mismatch, active sender/campaign, unfinished connection installation/job/lock, physical uncertainty or unstopped execution denies before sealing. Plaintext, unreadable Fernet and already scoped source material are not converted. Current-source ciphertext alone supplies no missing ownership evidence. The new command installs no Webshare application API key.

Existing stopped IPRoyal assets remain compatible, including the prior explicit sticky-owner path without a workspace field. Old IPRoyal service/pilot calls may omit the new evidence reference; new private CLI calls require it. A version-one saved receipt retains its original codec-dependent material comparison, including naive embedded assignment timestamps. Such an old receipt does not claim complete custody-policy proof: `configuration_matches` is false when it has no target-policy digest. No receipt retry resumes a campaign, changes a lease or repeats credential installation.

## Review and transaction protocol

The read-only inspector returns bounded record references, sender IDs, an exact normalized snapshot digest, blockers and `activation_allowed=false`. It does not return an IP, password, encrypted password, raw source record or decrypted credentials. Source/authority timestamps normalize to UTC BSON milliseconds; dispatch read-fence counters are excluded. The snapshot binds the complete custody mode/environment/KMS configuration, workspace erasure state, disabled gates, inventory, lease, matching account aliases and execution/connection/physical/campaign authorities. Malformed provider terms deny rather than becoming capacity.

Migration requires identified all-writer/cache drain and all four gates off: live outreach actions, integrations, Voice Studio and voice preparation. The drain is an operator assertion; this code does not inspect a real worker fleet or flush its caches. The target mode must be `kms_v1` and the exact current inspection must have no blocker. Existing matching authority rows are fenced within snapshot/majority workspace-guard transactions. Actual standalone Mongo cannot install credentials; there is no transaction fallback.

The first database-only transaction rechecks any exact concurrently saved receipt **before** comparing the original source or opening its password. Outside Mongo, strict Fernet opening and scoped sealing preserve the original Webshare generation. Complete policy and disabled-gate checks run after sealing. The final database-only transaction rereads/fences the exact original review, CAS-updates inventory and every matching sender alias, and saves a permanent metadata-only receipt together. Final policy/gate/provider-term checks precede callback completion. Mongo commit can follow that check; this is not an instantaneous configuration/expiry consensus or a socket/kernel guarantee. Database transaction retries reuse the prepared ciphertext and never repeat key work inside a callback.

The receipt binds operator digest, supplied evidence digest, original review, full after-material/basis/lease/IP-binding digest, target policy, generation digest, original Webshare basis and storage-conversion provenance. Operator or evidence mismatch cannot reuse another review. Exact retry returns only current material/configuration comparisons and historical completion, without opening the old source or resealing it. Both ordinary and guarded concurrent retries recognize the receipt, including a lost final-commit acknowledgement. Two callers that both pass preflight before either finishes may each seal once; only the guarded final projection commits. This is not exactly-once KMS billing.

Provider-term extension, password rotation, assigning a different owner/resource, activation and vendor-side ownership checks are deliberately separate protocols. No possible/unknown HTTP outcome is cleared or replayed; this migration makes no provider request. Replacement aliases/resources remain intact on review change or failed projection.

## Retention and operator use

The existing retention-first startup removes credential-migration and physical-exclusion TTLs before strict indexes. `_id` remains the unique migration receipt identity. No new collection or broad historical cutover is added. Account erasure purges ordinary proxy migration journals but retains minimal hashed original review/basis/policy/generation/operator/evidence/material provenance and completion time in a `proxy_custody_migration` hold. It copies no password, ciphertext, raw IP, sender cookie generation or raw reviewer. Permanent physical exclusion remains unchanged. Once erasure stops the workspace, absent/purged receipt retries cannot install, recreate authority or reopen it. Separate provider-term retention and cleanup rules remain in force.

Use `python -m outreach.ops.proxy_custody inspect --workspace WORKSPACE --asset webshare:PLAN:RESOURCE` after disabling gates and draining all participating writers and caches. Review the returned blockers and exact `digest`. Then run the `migrate` command with the same references, `--operator`, `--evidence-digest` (64 lowercase SHA-256 hex), `--review-digest` and `--workers-drained I_PAUSED_AND_DRAINED_ALL_WORKSPACE_WRITERS_AND_CACHES`. The private command accepts no proxy URL/password/cookie arguments, sanitizes parser/runtime failures and closes its Mongo client when database selection or execution fails. Operator references/digests are metadata; do not put secrets in them. See [paid pilot runbook](OUTREACH_PROXY_PROVIDERS.md).

Keep deployment and fleet/configuration cutover separate from a real live pilot. Configuration proof is process-local. Real IAM/temporary-role enforcement, kernel/process egress, backups/restore, provider validity and policy-approved live sender behavior remain operational evidence. Default legacy custody and disabled flags remain unchanged. No real AWS/vendor calls, purchases, grants, production changes, commit, push or deployment occurred.
