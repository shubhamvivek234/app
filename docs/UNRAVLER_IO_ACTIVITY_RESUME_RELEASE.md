# Unravler.io — Completed-task activity paging and resume
Version: 2.63.0 | Updated: 2026-10-13 IST | Status: Local, uncommitted, undeployed

The Home feed previously selected the newest ten completed tasks and moved its read boundary to the current clock. A burst could permanently omit older eligible rows; reconnect had no event position. This bounded A15 P2 change pages the retained task timeline chronologically and supports an explicit reconnect position. It does **not** complete an immutable activity/event history.

## Implemented behavior

- The [producer](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/activity_stream.py) reads 100 metadata-only task rows per page, ordered by `(updated_at, id)`, and immediately drains full pages. The boundary moves only to an emitted row. Idle polls never move it to the clock. The existing unique workspace/task-ID contract supplies the tie breaker.
- SSE task frames contain an `id` and matching `event_id`. The [endpoint](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/api/analytics.py) accepts the browser's `Last-Event-ID` header. The bounded versioned token contains the task timestamp/ID and a workspace fingerprint; it is an untrusted selection token, never an authorization credential or authenticated completeness proof.
- Initial admission reads the last ten minutes. Browser reconnect can resume a position up to 24 hours old while that exact completed-task anchor remains retained at its original timestamp. Malformed, foreign-workspace, expired, future, removed or modified anchors produce `stream_closed/resume_unavailable`; the producer does not silently restart at a different position. Unicode and default naive BSON dates round-trip correctly.
- Current original-workspace user/identity/membership/owner/erasure checks still run before task reads and each buffered emission. Five-second read limits and the original 300-second generator deadline remain. A normal deadline ends the stream, allowing native EventSource reconnect with its last position. Last-check-to-send revocation races and socket backpressure are not made atomic.
- [Home](/Users/shubham/Documents/Workspace/SocialEntangler/app/frontend/src/outreach/pages/OutreachHome.js) deduplicates observations and displays the latest 20. A transient transport error hides them; a fresh admitted greeting restores the mounted component's retained cache. Terminal controls and unmount scrub it. Seen IDs are bounded to 4,096 and are not persisted across page reloads.
- Copy identifies **Completed Task Activity** and explicitly states that these observations do not verify sends, replies or campaign health. Heartbeats only describe this connection.
- [Runtime indexes](/Users/shubham/Documents/Workspace/SocialEntangler/app/db/indexes.py) add `(workspace_id, status, updated_at, id)` for the chronological scan. The actual native index cutover is exercised on an owned database.

## Coverage limits and remaining A15 work

This source is a **mutable task projection**, not the durable outbox or an immutable execution journal. Late/backdated commits behind the last pair can be absent, including a same-millisecond completion whose ID sorts before the cursor. Repairs may change a task timestamp and appear as a new observation; anchor changes explicitly prevent resume. Pagination is not a snapshot under concurrent mutation. Initial history is ten minutes, browser reconnection is bounded, and refresh starts a new recent view.

The tests establish draining and resume for retained, ordered task records, including existing timestamp ties. They do not establish complete historical delivery, actual provider outcomes, recipient/enrollment lineage or reply/acceptance/manual-event coverage. An immutable insertion-ordered event surface with writer coverage, retention/gap semantics and migration remains unfinished. A15 must not be marked fully closed on the strength of this slice.
