# Unravler.io — User Lifecycle and IP Provisioning
Version: 2.22.0 | Updated: 2026-10-05 | Status: Corrected baseline and implementation contract

## Evidence and scope
This specification covers LinkedIn outreach. Social publishing and Smart Bio belong to the wider Unravler product and have separate integration permissions.
“Local” means the named repository path exists and has automated evidence. “Target” means implementation or operational verification remains outstanding. Tests do not verify provider behavior or authorize private-endpoint automation.
Baseline: local commit 2187946; 355 outreach backend tests passed during the architecture review. Subsequent changes must record their own validation.

## Access modes
| Mode | Behavior | Permission boundary |
|---|---|---|
| Official integration | Publishing through an authorized integration and granted scopes | Integration-specific permission |
| Manual preparation | Customer-supplied CSV/pasted leads, stored-data staging, AI drafts, Engage draft/review | Workspace permissions; no automatic outreach submission |
| Private-endpoint access | Authenticated LinkedIn/Sales Navigator crawling, inbox/profile reads and mutations | Live-action gate, paid access, verified sender/proxy, shared physical budgets/ownership, expiring operator permission and operation-specific guards |

The authenticated search crawler is automated access even when started by a person. Do not describe it as risk-free manual import. [LinkedIn policy](https://www.linkedin.com/help/linkedin/answer/a1341387/prohibited-software-and-extensions).
Versioned risk disclosure and account-ownership attestation are target product requirements before enabling customer private-endpoint traffic. Consent is separate from platform permission.

## Commercial lifecycle
The pilot remains invite-only, $59 per sender per month, 1–5 senders per workspace, with one requested country per workspace. There is no public trial, self-issued entitlement, automatic proxy purchase, renewal, or cancellation.
1. Customer requests seats and a country.
2. Operator imports enough dedicated country-matched assets covering the paid period.
3. Operator verifies the external invoice and grants exact paid coverage.
4. Customer connects a sender using the workspace's assigned IP.
5. Paid expiry or revocation blocks new execution and pauses work; connected leases retain provider-term ownership.

Local evidence: outreach/core/paid_access.py, outreach/core/managed_proxy.py, tests/test_outreach_paid_lifecycle.py, tests/test_outreach_managed_proxy.py.
Receipt and entitlement writes currently require reconciliation if interrupted between writes. Do not advertise multi-record transactional payment processing.

Future Stripe events must be signature-verified and deduplicated, and reconciled against paid invoice coverage. Checkout completion alone is insufficient payment evidence. Set paid_through from validated coverage; never increment it blindly by 30 days. Handle out-of-order events, immediate revocation, cancellation at period end and independent pause reasons. [Stripe webhooks](https://docs.stripe.com/webhooks).

## Procurement and proxy assignment
Current country availability is a local inventory check. Live reseller product stock, plan IDs, quotes, account balances and automated orders are targets requiring provider verification. Do not advertise a live checkout/stock workflow.
Future purchases persist an order intent and spend bound before submission. A timeout/5xx that could have received the order becomes unknown; no blind repeat purchase. Poll or reconcile using verified provider references.
Asset expiry and paid access are different clocks. Retain disconnected sender ownership through the provider term; never transfer a still-bound IP to another customer.
Use expiry warnings and a justified execution-duration safety margin. A fixed 48-hour cutoff is not the pilot contract and must not silently remove two days of paid service.
Connection validation must verify the expected authenticated member, proxy route, response schema and country. HTTP 200 alone is insufficient.
Record actual purchased price and provider expiry from the order/invoice. Product 9/Plan 22/$4 figures are unverified account-specific inputs, not universal prices.

## Connection and credential lifecycle
| State/event | Required behavior |
|---|---|
| Connect requested | Valid paid access, same-workspace available asset, one sender lease |
| Verification succeeds | Store encrypted credentials, active sender identity, credential generation |
| Known pre-activation failure | Scrub job secrets; release only proven unused v2/fenced reservations owned by this job; quarantine legacy ambiguity |
| Permission/capacity denial before transport | Keep encrypted pending values and reservations; persist next verification due time; custody ends at original capture +15 minutes, with a 60-second available-worker cleanup service objective |
| Credential-write acknowledgement lost | Retain finalizing job, generation, IP, slot and lock; scrub pending values on caught failure, stop grants and require drained operator repair |
| Reconnect succeeds | Keep same valid assigned IP; replace credential generation and invalidate inbox freshness |
| Disconnect/checkpoint | Revoke execution, pause affected campaigns, invalidate freshness; retain provider-term ownership |
| Paid expiry | Block workers, scrub session/pending-job secrets; retain already-connected asset leases |
| Provider expiry | Deny use and retire the asset/assignment with audit evidence |

Local preparation creates no usable new session. Installation matches the exact account-local fence, job/owner/base/prospective generation and server-time custody deadline; completion rejects expired custody. A 60-second cleanup schedule scrubs pending secrets with live flags disabled and closes/scrubs only the original account generation. Unresolved jobs omit TTL-indexed created_at until cleanup is complete. Drained operator repair records provenance, retains possibly installed assets and resumes only saved database repairs. Pending grants are job-bound and capped at the original deadline. This is not offline deletion, cached-memory erasure or universal KMS custody.

Default custody remains legacy Fernet. The opt-in local KMS/AES-GCM foundation now covers LinkedIn cookies and managed IPRoyal passwords, with separate session and asset contexts and private drained migration. It has no verified deployed AWS/IAM/egress/restore evidence; other provider/shared-secret types remain unfinished.
No cookies, credentials or plaintext message payloads belong in broker messages, public errors or operational logs. Verify sanitization separately from encryption.

## Campaign authorization
Campaign authorization consists of status, revision, pause_reasons, sequence identity and sender assignment. Only an explicit launch/resume may authorize work after all relevant guards pass.
Pausing, deletion/restoration, sequence edits, sender reassignment and administrative revocation invalidate earlier execution revisions. Clearing one reason does not remove another or automatically resume.
Persist immutable sequence versions and enrollment identity. Deduplication identity must not change merely because a worker restarts, a campaign resumes, or a sender reconnects.
Preserve legacy lead:node operation records; uncertain legacy actions cannot become fresh sendable intents.

## Freshness and stop-on-reply
Polling reduces unobserved-reply exposure; it cannot eliminate all remote reply races.
A valid freshness marker is scoped to workspace, sender, channel and credential generation. It records coverage start, completion, parser version and completeness. Freshness is based on covered data, not simply time of task completion.
Missing, future, partial, capped, malformed or old-generation markers block follow-up mutations and request deduplicated priority sync. A capped 500-conversation scan is not proof of complete account coverage.
Inbox synchronization can run without an already-fresh inbox. Search reads use their own access/budget guards, not inbox freshness. Email uses its existing mailbox cursor contract.
Before authorizing a mutation, recheck reply/DNC state and campaign/sender permissions. Conditional completion updates cannot overwrite concurrently recorded suppression. Explicit reply-conditioned branches retain their defined semantics.
Local: final dispatch revalidates and writes applicable authorities in one snapshot transaction with majority commit. Dispatch and participating DNC/email/LinkedIn/mailbox suppression writers first write the same stable workspace guard; new matching inserts and identity changes therefore conflict or are seen on retry. A recorded stop committed before dispatch authorization blocks it. Authorization committed first may complete; time/freshness/schedule checks run synchronously after commit and before transport. The guard is initialized with majority read/write concern before the snapshot, never upserted inside it, and has no TTL/reset. Missing guards or unsupported transactions deny. Raw database writes, older runtimes and unmapped recipient identities are outside the protocol; drain every older participating writer before rollout.

## Intent, attempt and recovery
ActionIntent identifies workspace, enrollment, sequence version, node and action kind. ActionAttempt records one physical submission and its evidence.
Persist intent before worker publication. Broker redelivery is not a new provider attempt. Claim ownership, possible submission and result recording have distinct transitions.
An expired claim can be reclaimed only while no possible-submission boundary was crossed. Any crash/timeout after that boundary preserves unknown outcome and requires reconciliation.
Provider acceptance, observed sent, observed delivered and human assertion remain distinct. A 200/URN is not proof of delivery.
Current outreach_tasks already supplies a unique workspace/operation boundary and conservative uncertainty handling. Preserve it throughout migration.

## Content review and manual-action authority
Local: exact human review expires after 24 hours and binds sender/generation, recipient, finished content, campaign/sequence/enrollment identity and policy. Changes require another review. Content approval is independent of billing, sender permission, campaign execution and outcome evidence.
Explicit manual Send/Comment/Like clicks record an identified actor and exact choice in durable jobs; broker payloads contain references only. Workers revalidate the saved context. Cached voice clips are encrypted, digest-bound and expire after 24 hours; the review API does not call voice providers. Email review includes mailbox identity and effective body; email/finder sends and billable lookups now pass provider-specific physical envelopes, with fixed endpoints, resource-bound permission and immutable MIME/lookup subject checks.
Received manual stages repair reporting without resend. Unknown outcomes retain target ownership and require drained reconciliation. Administrators may renew a current approval or cancel a queued proven-unattempted remainder; this cannot erase completed stages or override uncertainty. Final dispatch now transactionally revalidates existing matching approval/permission/paid/campaign and applicable job/target authorities before HTTP. The shared workspace guard now orders participating suppression inserts/identity changes too; subsequent transport response/projection writes retain their recoverable boundaries. Owned outreach erasure/retention and account-worker integration are now verified locally; full writer drain, external cleanup and retention review remain operational requirements.

## Execution health, traffic and operational gates
Local: operator-issued execution permission lasts 1–60 seconds and binds workspace, sender, credential generation and allowed sources. LinkedIn reads/mutations and provider email_send/email_find boundaries check it. A provider grant binds sender generation plus mailbox connection identity or encrypted finder credential identity; provider sources cannot be mixed under one generation. The authoritative permission lives with sender ownership in outreach_sender_execution; the separate permission collection is a reporting projection. Final ownership/permission CAS and explicit expiry checks block new calls; expiry cannot cancel already-authorized requests. Automatic monitoring/renewal remains a target.
Target monitoring policy: operator halt or a permanent restriction latches execution off. Local operator stops and ambiguous mutation outcomes latch permission; a challenge/cohort monitor has not been implemented. Challenge monitoring is sender-scoped; use a 14-day sender-level cohort view with counts and denominators. A 5% alert at a minimum 20-sender sample is an investigation signal, not a competing undocumented 1% cluster permission rule. Below that sample, any challenge pauses the affected sender and requires operator review. Validate this policy before live release.
Local shared MongoDB budgets count every LinkedIn adapter subrequest, reserve sync/verification capacity, enforce sender/action limits and deny on storage failure. Legacy daily usage is preserved as a floor. Proven non-calls refund action allowance once; physical reservations stay conservatively charged. Search and verification deferrals use durable timestamps and 30-second publishers. Email/finder traffic now uses provider-specific policies over the shared ownership/budget/receipt envelope, including 100 email/day and 10 finder/day pilot workspace ceilings with tighter sender/campaign caps. Public proxy health/inventory, OAuth refresh, mailbox sync and voice/model vendors remain separate.
Kernel egress isolation and restore fencing are targets requiring implementation and drills. No-default-route alone does not prove proxy-only transport; specify DNS, proxy, database, broker and control-service routes including IPv6.
Live actions stay disabled until explicit release authorization and operational evidence for purchased assets, sender verification, mailbox pilot, custody, routing and recovery.

## Account/workspace erasure and retained authority
Deletion persists a pending user and all actually owned workspace IDs before generic cleanup. The selected shared workspace is not ownership. Legacy private user-ID scopes are included only after proven ownership; capacity/unknown-collection failures remain pending. All tenants, including empty ones, await an identified operator's full writer drain and current inspection digest. Stop and bounded database-only cleanup share the stable workspace guard; secrets are scrubbed before content purge. Fresh reviewed retries revisit partial batches and recheck unexpected late rows. Cached credentials and older/raw writers require actual operational drain.
Minimal unresolved submission, known receipt, unfinished connection cleanup, financial and provider-term references may remain under explicit retention review. Known queued/accepted/completed work is not relabeled uncertain. Sanitized IP leases remain tenant-bound until current owned-asset expiry is independently verified; no provider cancellation or auto-renewal is implied. The closed workspace guard, Firebase UID digest and invoice/term binding digest have no TTL or reopening/reuse path. Digests are pseudonymous exclusions, not a legal retention or anonymization claim. Other owners' shared business data is preserved.
The durable account retry publisher and external cleanup retain pending users/references on failure. Customer status/copy does not claim universal immediate erasure or completed deletion on failed/unknown lookups. Backups, remote copies, whole-product data coverage, legal retention decisions and live provider/SDK behavior remain separate. ## Local managed proxy custody and orphan storage repair
Managed IPRoyal password custody is locally implemented in the opt-in `kms_v1` mode. Its authenticated context binds workspace, canonical asset ID, credential generation, transport metadata, purpose and environment. Sender ownership remains a separate one-sender lease and final authorization check. Imported inventory and embedded sender copies retain custody metadata; KMS mode refuses unscoped legacy assets. At the twelfth-slice boundary, mailbox/finder/voice/shared-secret custody, Webshare provisioning and actual workload IAM remained separate; the thirteenth slice below supersedes the mailbox/finder scope.
Each transport opens the proxy before authorization and captures the exact encrypted asset plus actual URL from the same snapshot. Mongo authorization compares that prepared binding against the current sender and inventory without KMS calls; replacements, workspace swaps and stale generations deny transport. Drained migration updates a managed asset and its proven sender aliases with an atomic metadata receipt, preserving leases, installed cookie generation and stopped permission. A saved receipt retries without key calls or automatic resume.
New connection locks retain a reference-only base-account/resource proof before attempting pending insertion. A private, all-writer-drained, live-disabled stop can close an absent job only when that proof still matches and no verification/installation evidence exists. It atomically stops permission, saves a permanent reference-only closure and removes only job-owned unused reservations/lock. Existing reconnect credentials and reused leases/slots remain held; older ambiguous locks, changed accounts, physical evidence or a now-present job require separate review. The closure omits TTL-indexed `created_at`; late insertion cannot reopen it. Workspace erasure can purge ordinary closure metadata only behind its permanent workspace exclusion. The connection dialog recognizes stopped terminal states. Procedure and evidence: [Proxy custody and storage repair](UNRAVLER_IO_PROXY_CUSTODY_AND_STORAGE_REPAIR_RELEASE.md).
