Updated: 2026-10-14 IST. F2 is local, uncommitted and undeployed. This extends the [F1 foundation](UNRAVLER_IO_AUDIENCE_LIST_FOUNDATION_RELEASE.md); earlier checkpoint statements about unfinished UI are historical.

## Behavior

Leads now opens an Audience lists dialog for an existing campaign, including a campaign created through the existing campaign workflow. Users can create, rename and archive named lists, browse 50 memberships per page, add up to 100 selected contacts from that campaign, remove memberships, and import a reviewed CSV/public-profile prefix into a selected list. Empty, unavailable, stale, orphaned and archived states have separate controls and copy. List membership organizes an existing campaign enrollment: archive/removal does not pause, stop, delete, duplicate or grant execution. Collection completeness is always unverified. Available membership means a recorded contact reference, not send eligibility.

HTTP rename/archive/member writes now require the current catalog `review_digest` as well as revision. The digest binds original native list and campaign identities. Internal F1 compatibility helpers retain their explicit optional argument; old HTTP clients must refresh/use the new token. Imports always require it.

## Bounded source review

The dedicated list importer accepts CSV or pasted public LinkedIn `/in/` profiles, with an explicit quantity from 1–100 input records and at most 2 MB of UTF-8 source. It streams only that prefix plus one sentinel before materializing parsed contacts. Empty CSV records and blank pasted lines do not consume the prefix; nonempty invalid and duplicate rows do. BOM/quoted headers are preserved. Header and selected-record width is capped at100 columns before dictionary parsing; Unicode pasted-line boundaries match the existing parser without materializing the unselected suffix. The sentinel is observed without parsing or validating an unselected contact. A sentinel establishes only that more input rows exist; the remaining/full source total is unknown.

The server reparses the original source, including its email and suppression identities, when committing. Only first-name overrides by canonical reviewed row number are accepted; an explicitly empty name clears every effective fallback and is excluded when names are required. Request, map-key/value, Unicode and source bounds are checked before hashing or phase-one persistence. The optional F2 history bound projects exclusion identities/reasons and denies when any individual matching policy query exceeds 1,000 rows. This is a row bound, not an authenticated historical completeness or strict byte-memory proof. Existing generic intake paths retain their previous lookup behavior; this slice does not declare them fully bounded.

For this public-profile slice, supplied member/transport-URN CSV columns are rejected in the selected prefix, including URL-A/recipient-ID-B conflicts. A source URL never authenticates a supplied transport identity. Verified premium identity resolution and old generic/legacy recipient-identity cases remain F4; no resolver or premium acquisition is invented. Search remains unavailable under F0. The dedicated importer does not support all generic CSV mapping/tag options or source collection.

## Original request and atomic commit

`outreach_lead_list_imports` stores only a scoped actor/request UUID, original target metadata, native/revision/context/input/parser digests, selected quantity, UTC timestamps, state and bounded row-number/decision/lead-reference receipt. No raw CSV or per-contact profile URL/name/email/exclusion-reason fields are copied into the control. The user-supplied list display name is retained as organizational target metadata and may itself contain personal data; actor/lead references and hashes are pseudonymous, not anonymous. Guarded workspace erasure covers that metadata. The unique workspace/actor/request index has no TTL; guarded workspace erasure includes this collection. Existing strict index conflicts are retained, never silently deleted or adopted.

This local database-only path adds no competing queue or provider worker. Phase one persists a pending request under the shared workspace guard and captures the original list/native campaign identity, list revision, campaign draft/paused state, authorization revision, actor scope, parser contract and parsed-content digest. Phase two revalidates those exact values under the same snapshot/majority guard, runs the existing mandatory admission policy, inserts contacts and membership, advances the list revision and stores the completed receipt in one transaction. Only draft/paused campaigns accept this workflow. No launch, sender assignment, authorization grant, queue publication or provider call occurs. Standalone MongoDB denies the operation.

The stable input digest is separate from parser version. A pending request cannot silently adopt changed parsing, options, edits, quantity, list/campaign/native identity or authority. A completed retry/inspection reports its original receipt without reparsing, requiring a current parent/contact or reenrolling anyone. Parser upgrades do not reinterpret completed receipts. Structural/context/count/row consistency failures stay review-required.

## Cancellation and response loss

Cancellation is ordered against the same database commit. It closes a pending request without admission. If completion wins, cancellation returns that original completed result and does not claim that contacts were removed. Cancelling an as-yet absent UUID writes a cancellation tombstone; an in-flight phase-one request cannot later commit under that UUID. A missing/read-failed status remains unknown; it does not prove cancellation or non-admission.

Before submitting, the browser saves only the actor/workspace-scoped request UUID reference in a bounded session inventory. No source/contact data is persisted there. Unknown outcomes retain the original reference; the user can inspect/cancel it, or retry the identical in-memory request. Reopening checks the saved original request even if the selected parent/list was subsequently changed or removed. A result arriving after the dialog closes retains its reference for presentation on reopen. Terminal responses cannot be undone by an older pending response. Malformed status/receipt/storage does not become a success or an automatic new request. Browser session loss remains a limitation: this is not a durable account-wide import-history UI.

List-create response loss similarly retries the original UUID/body. Known pre-write name/limit rejections permit correction. Mutation failures hide unconfirmed member controls until refresh. Final import reports show original row numbers with imported/excluded decisions and codes, separately from requested/considered/imported counts. A newly chosen file cannot reuse the previous file while reading.
