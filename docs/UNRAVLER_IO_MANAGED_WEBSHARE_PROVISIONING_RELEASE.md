# Managed Webshare provisioning — v2.27

Updated: 2026-10-08. Status: locally implemented and verified. Uncommitted and not deployed.

## Result and scope

The paid sender path can reserve manually verified, already purchased Webshare dedicated static ISP IPs alongside the existing IPRoyal inventory. The private operator import records workspace, country, plan, proxy resource, original order and provider expiry. This is operator-asserted evidence with an identified reviewer and a SHA-256 reference to the independently retained original evidence. It is **not** an API result, vendor ownership attestation or an automatic purchase/renewal/cancellation operation. The existing bounded Webshare API selection helper remains separate from managed paid inventory.

No customer API or new checkout is added. Customers still request their intended country; an operator verifies capacity and payment separately. No real provider/AWS calls, payment grants, production configuration changes or flag enablement were performed. Default legacy credential custody and disabled live/generation flags remain unchanged. Frontend is unchanged.

## Durable local assignment

The new import ID is `webshare:{plan_id}:{resource_id}`. An immutable normalized metadata digest binds tenant, sticky ownership, public IPv4/authenticated HTTP transport, country, original plan/resource/order, exact UTC BSON-millisecond expiry, credential generation/custody workspace, manual evidence/operator/timestamp and request identity. Only dedicated, nonrotating static ISP capacity with a future verified term is accepted. The URL is bounded to 2,048 characters and credentials to 256 characters; private/non-IPv4 hosts, malformed URLs, control characters and ambiguous identifiers deny. Passwords are encrypted under the existing default Fernet or opt-in scoped proxy custody. KMS access occurs outside database transactions.

`account_proxy_ip_guards` stores only an IP-derived digest and an immutable workspace/asset/provider binding digest. It contains no raw IP, tenant, resource, operator, secret or timestamp. Its unique primary key orders participating imports across workspaces/providers; current global inventory collision checks expose only collision presence. Both new Webshare imports and the existing IPRoyal import join this protocol. Existing same-ID ownership/transport conflicts deny before a permanent claim or key call. The system guard survives tenant erasure and expiry, so a claimed physical IP cannot be imported under another customer, provider or resource; a new resource distinguished only by a different port cannot bypass it. Older/raw writers and previously erased unclaimed history remain outside this protocol; the guard does not prove historical exclusivity or actual vendor allocation.

Preflight commits physical exclusion before sealing; a key or final-insert failure can therefore leave a permanent claim without usable capacity. The same workspace/resource may retry after inspection. A changed owner/resource cannot take that orphan claim. Final import revalidates exclusion and policy under the workspace guard, then atomically inserts inventory. Exact retries of a committed import reuse the original ciphertext/generation without key access, provider calls or secret rotation. A different password in a retry is ignored: `already_imported` means original credentials remain installed. Changed term, country, order, resource, transport, operator or evidence require a separate reviewed workflow. A mode cutover does not adopt/reseal an existing asset.

## Paid sender and installation boundaries

Reservations now run in the existing snapshot/majority workspace transaction. They select at most 100 current country-matched provider rows, skip already leased assets, and retain one unique lease per sender and asset. Missing/manual-basis/physical-exclusion failures block Webshare selection. Reconnect reuses the exact existing lease and reservation owner. Expired-lease retirement and its history commit only when a replacement reservation succeeds; a failed replacement transaction keeps the original lease/history intact. No other country is substituted.

Payment capacity counts eligible IPRoyal rows and at most 100 Webshare candidates that pass the current manual basis, physical claim, term and configured custody-format checks. This capacity read is not an atomic billing/asset allocation transaction and does not prove decryptability. Actual reservation, verification and installation independently recheck their own authority. Existing invoice/entitlement behavior and its separate reconciliation limits are retained.

Webshare sender readiness requires the current local import, claim, term, country/provider-specific sender lease and exact embedded transport/ciphertext identity. Pending connection verification checks the import before health/key work and again at the final request authorization. The worker rereads it after identity verification. New Webshare credential installation revalidates paid access, live gate, slot, exact lease, import/term and prepared material within a guarded transaction that writes matching authority rows and the account fence together. Drained installed-session inspection rejects missing or changed import proof. These are authority checks at the relevant transaction/adapter boundaries; they do not prove actual provider IP behavior or make database commit instantaneous.

Prepared proxies now capture the complete custody mode/environment/KMS configuration. Sealing/opening reject an awaited policy change; metadata checks require the captured policy and URL integrity without key access. LinkedIn dispatch synchronously repeats this pure proof after the final authority transaction and immediately before entering its adapter factory. A policy change there is a proven non-call: evidence remains `not_submitted`, allowance can refund and the matching physical token clears. This does not add a kernel egress rule, DNS/socket/first-byte check, cross-process configuration consensus or memory zeroization guarantee.

Strict startup requires the existing unique sender-lease index instead of tolerating duplicate legacy leases. All touched evidence TTLs, including the physical IP guard, are removed before strict builds can fail. Conflicting old leases fail startup for drained operator repair; there is no fallback to standalone Mongo. Permanent claims and original provider terms remain evidence, not paid access or permission.

## Operator use and remaining work

The private command is `python -m outreach.ops.webshare_inventory`. Provide workspace, plan/resource/order, country, explicit timezone expiry, operator and original evidence SHA-256; explicitly confirm dedicated static ISP capacity. Supply the authenticated URL through the hidden prompt or explicit bounded stdin. There is no URL/password argument, echo fallback or credential output. Parser and operation failures use static messages, and Mongo clients close on failure. The command does not install an application Webshare API key or grant payment/sender permission. See [paid pilot runbook](OUTREACH_PROXY_PROVIDERS.md).

Deployment requires a drained index/configuration cutover, operator evidence review and separate technical/policy authorization for any live pilot. Native old Webshare helper rows, unproven/ambiguous historical leases, managed Webshare Fernet-to-scoped migration, term extension/credential rotation and vendor-side ownership checks remain separate work. Existing `ProxyMigration` continues to deny Webshare assets. Remaining shared-provider credentials, explicit integration activation, installed older-artifact cutover, different-key/unproven voice evidence and actual IAM/process/kernel egress/restore/pilot verification remain outstanding.
