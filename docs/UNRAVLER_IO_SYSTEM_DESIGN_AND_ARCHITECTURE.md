# Unravler.io — System Design and Architecture
Version: 2.22.0 | Updated: 2026-10-05 | Status: Corrected baseline, recovery protocol and implementation sequence

## Evidence and architecture decisions
Baseline: local commit 2187946; 355 outreach backend tests passed during the review. Runtime deployment and provider verification require separate evidence.
The architecture uses FastAPI, Motor/MongoDB and Celery/Redis with a Python private-endpoint client for gated LinkedIn traffic. Direct HTTP reduces browser dependencies but carries schema/authorization risk. RAM/latency numbers require measurement and are not verified guarantees.
Recorded fixtures verify known parser contracts; they cannot detect every future upstream change. Unknown response schemas must fail closed.
The six domain concepts are independent authorities, not an instruction to replace existing IDs/collections. Keep manual paid provisioning until commercial automation is needed.

## Current topology and target isolation
Current outreach worker registrations use the outreach queue. A queue name does not establish dedicated worker/process isolation.
Target:
- API writes tenant-scoped configuration and durable work references.
- Scheduler selects due work from MongoDB; broker carries IDs, trace/owner tokens and revisions only.
- Transport workers validate permissions immediately before physical submission.
- Inbox workers durably commit replies before publishing complete coverage.
- Generic webhook/model-provider egress is separate from LinkedIn proxy transport.
- Control monitoring has explicitly bounded repair/probe permission.

MongoDB is the action/authorization authority and now holds the shared LinkedIn physical-request budget. Redis remains the broker and supports other legacy coordination; neither broker delivery nor a budget reservation proves provider delivery.
Final physical dispatch now requires sessions and multi-document transaction support, without a production fallback. Verify the actual deployment supports snapshot transactions and majority commit before rollout; unsupported standalone servers deny transport. Other single-document transitions and explicit recoverable workflows retain their own boundaries.

## Authorization and preflight
Only explicit launch/resume grants campaign execution. Revision changes fence earlier queued work. Reasons are independent: operator pause, billing expiry/revocation, sender stop, unknown outcome, deletion/restore review and content-policy failure.
Target universal business-authorization protocol: the foundation integrates campaign sequence intents/attempts; the second slice shares the LinkedIn physical boundary across sequence, sync, search, inbox replies, Engage and verification. The third slice adds exact content approval and durable manual stage/receipt/projection recovery. Drained manual-stage/finalization resolution is now local. The seventh slice transactionally revalidates and fences existing matching/read authority rows. The eighth adds a shared workspace guard for dispatch and participating DNC/email/LinkedIn/mailbox suppression writers, including new matches and identity changes:
1. Verify deployment feature gate and any required positive execution lease.
2. Verify workspace entitlement paid coverage and revocation.
3. Verify sender identity, credential generation, assignment and provider term.
4. Verify campaign active status, empty blocking reasons and matching authorization/sequence revision.
5. Verify current lead/DNC/suppression state and applicable content approval.
6. Verify channel-appropriate freshness and working schedule.
7. Reserve sender ownership and applicable physical-request budget.
8. Persist conservative possible-submission evidence. Ensure the stable workspace suppression guard using majority read/write concern before the snapshot; write it first in the transaction, then revalidate applicable authorities, write their fences, authorize the exact sender/content token and record dispatch authorization. No HTTP runs in this transaction; retries repeat database work only.
9. Submit once; preserve evidence and uncertainty.

Permission expiry blocks new authorization. It does not cancel already-submitted remote requests. State the dispatch authorization transition as the local ordering boundary.

## Positive execution permission
Local: explicit operator grants last 1–60 seconds, bound to workspace/sender/generation and the sequence, sync, search, inbox_reply, engage or verify source. Missing, expired, stopped, malformed or unreadable authority denies transport. Permission is embedded in the sender-ownership document; the standalone collection is a read-only projection. Workers check expiry explicitly.
The final physical-request token CAS matches the current owner, in-flight state, absence of another physical token and active same-generation/source permission. It now shares a snapshot transaction and majority commit with content authorization, physical authorization evidence and write fences on applicable existing matching/read campaign, paid-access, sender/proxy, lead/thread, job/target, provider resource and intent/attempt rows. Immutable sequence versions stay read-only under the fenced campaign/version binding. After commit/session closure, captured deadlines and working hours are rechecked without another asynchronous operation before transport. Participating suppression writers write the same workspace guard before reading or mutating suppression state, so new matches and identity changes now order with authorization. This is a participating-writer protocol, not MongoDB predicate locking; raw database writes and older runtimes remain outside it. Budgets, earlier possible-submission markers and later outcome/projection writes retain their recoverable boundaries.
Separate sender health from cluster/operator permission. Use Document 1's consistent challenge policy; remove the conflicting undocumented 1% threshold.
Monitor inputs need timestamps and scope. A healthy generic proxy probe cannot authorize an unhealthy assigned proxy.
Local operator stop and mutation ambiguity latch permission; renewal cannot silently clear the latch. Explicit unlatching also cannot bypass unresolved physical submission or connection finalization.
A 30-second health monitor and automatic renewal remain targets. No monitor is running in this slice, and expiring permission cannot cancel an authorized in-flight request.

## Scheduler semantics
Local fourth slice: the periodic selector persists action intents and immutable due-occurrence sequence jobs in MongoDB before separate publication; no provider work runs in the selector. Brokers receive workspace/job IDs. Per-job workers claim both job and lead and revalidate original enrollment, sender/generation, node, immutable sequence digest/version, campaign revision, state and due time. Stale deliveries cannot execute a later step. A 30-second recovery task repairs exact matching received outcomes or quarantines interrupted submissions without transport. Due ordering/backoff rotates missing projections and invalid scan candidates.
Local second slice: shared LinkedIn sender coordination and request budgets; search page and verification deferrals persist due timestamps in MongoDB. Separate 30-second publishers enqueue due identifiers; worker owner/status/cursor checks fence duplicate or stale deliveries. Publication failure leaves due work available. Long crawler countdowns have been removed.
Multi-day sequence delays remain durable lead timestamps. Repeated condition polls receive a new due occurrence so a completed check cannot suppress later checks. Real isolated Redis/Celery SIGKILL/redelivery drills exercise this dispatch/outbox protocol with fake effects; the sixth slice verifies physical receipt/token recovery for four production adapter paths through loopback HTTP and real worker-kill/redelivery drills.
Celery redelivery depends on configured visibility_timeout, not a universal five-minute threshold. [Celery guidance](https://docs.celeryq.dev/en/stable/userguide/calling.html#eta-and-countdown).

## Intent/attempt state protocol
Logical identity: workspace + enrollment + immutable sequence version + node + action kind. Sender/content/policy bindings belong to authorization revisions and canonical hashes.
| State | Allowed transition | Recovery |
|---|---|---|
| pending/deferred | Owner claims with token and expiry | Durable scheduler can rediscover work |
| claimed, no possible submission | Current token may authorize submission | Expired token may be replaced atomically; stale workers reject |
| possible submission / in flight | Same owner records outcome | Expiry/crash becomes unknown, never automatically pending |
| provider accepted | Advance under conditional lead-state guard | Repeated broker delivery reads recorded outcome |
| unknown outcome | Reconciliation with explicit evidence | No blind retry; may remain unknown or be stopped |
| canceled/suppressed | Terminal for that authorized action | Resume does not erase suppression/history |

Persist intent before publication. Publishing may be repeated safely; execution claims are authoritative. Broker IDs do not authorize a provider call.
Store claim token, authorized revision, credential generation, due time, possible-submission time, result evidence and audit timestamps. Physical attempts record sender, transport stage, provider reference and evidence class without credentials.
For atomic embedded attempts, the intent document is the durable physical-attempt authority; any separate reporting projection is recoverable and cannot authorize a resend.
For separate attempt documents, use verified transactions or a documented repair protocol. Never imply atomicity from two ordinary writes.
The acceptance suite must cover broker publication failure, duplicate delivery, stale owner, queue delay, timeout, crash before/after possible submission, and database failure after provider acceptance. First-release tests cover atomic claims, simulated duplicate worker delivery, stale owners, reply/review/recovery races, projection failure, and database failure after submission. The second slice adds simulated broker failure for search/verification publication. The fourth slice verifies real isolated Redis/Celery worker-kill redelivery and unavailable-broker publication with fake provider effects; the sixth slice adds physical receipt/token worker-kill checks through production adapters and loopback HTTP, preserving uncertainty when no response was durably saved.
Keep legacy action claims until their migration is proven. Preserve accepted/completed/uncertain and human-resolution provenance.

## Inbox coverage and reply ordering
Baseline LinkedIn sync runs every 300 seconds on outreach queue. The first local release adds completed markers and a 30-second priority-sync dispatcher.
Implemented local marker: workspace, sender, channel, credential generation, parser version, coverage start, completion, coverage/cursor and complete status.
Only publish freshness after durable reply/suppression processing. The covered-data timestamp determines age; completion time alone can hide a long-running scan.
Missing/future/malformed/partial/capped/old-generation coverage denies follow-up mutation and requests deduplicated priority sync.
The current 500-conversation cap needs a defined completeness contract; it cannot silently prove the entire account fresh.
Sync does not require already-fresh inbox state. Reserve sync capacity independently of prospect actions. Email uses its existing mailbox cursor and suppression rules.
Final eligibility checks and conditional advancement preserve concurrently recorded replies. Explicit reply branches have distinct semantics.
Local guarantee: suppression/revocation updates to applicable existing authority rows committed before transactional authorization block through conflict/retry. Dispatch and participating DNC/email/LinkedIn/mailbox suppression writers write a stable workspace guard before their snapshot lookups; new matching records and identity changes therefore cannot evade a negative lookup through those writers. The guard is majority-visible before the snapshot, never upserted within it, and has no TTL/reset. More than 100 matching threads conservatively denies. Stop-first denies; authorization-first may complete. Raw database writes and older runtimes remain outside this protocol, and unknown identifier relationships and remote replies not yet observed remain possible.

The pilot deliberately serializes participating work per workspace rather than enumerating recipient lock keys. Contention/timeouts fail closed; capacity/latency has not been measured. Database-only LinkedIn and mailbox callbacks commit reply suppression, stops, counters, thread/event records and applicable inbound markers together. Transient retries re-read current state and reuse outbox records; stale/equal/undated pages preserve newer saved metadata and idempotently merge observed replies. Immutable DNC identity-set records preserve older aliases; exclusion checks include saved identifiers and current discovered fields. Guard lifecycle deletion/reset must never race active writers; outreach erasure must stop/drain execution and preserve minimal recovery obligations first.

## Shared physical-request budget
Local: one atomic MongoDB sender/workspace budget reserves hourly, daily, foreground and action counters together. Defaults cap physical capacity at 120/hour and 1,000/day, with 20% sync/verification reserve; sender policy may tighten them. These are local ceilings, not platform-approved safe rates.
Every LinkedIn HTTP subrequest in Voyager/session adapters passes the common envelope, including pagination, identity resolution and verification. UI operations are not the counting unit. The actual configured proxy must equal the bound assigned proxy; there is no live unscoped-client fallback. Email sends and billable finder GETs use provider-specific fixed-endpoint, MIME/lookup and generation checks over shared ownership/budgets/receipts. OAuth refresh, mailbox synchronization, public health/provider inventory and voice/model-provider traffic remain separate; this is not universal egress isolation.
Action limits are shared across sources and tightened by sender/campaign settings. Preserve current-day legacy counters as floors. Physical reservations remain charged; a proven non-call refunds action allowance once using an independent reservation ID. The legacy RateBudget facade now uses MongoDB and denies storage failure; its process-memory fallback is removed.
Shared ownership spans sequence, crawling, sync, verification, Engage and inbox replies. A 30-second hard transport deadline applies. Mutation timeout/cancellation, interrupted evidence, ambiguous success or HTTP 408/429/5xx preserve uncertainty and latch permission.
Stable Engage/reply physical identities block replay after reporting failure. Only explicit not_submitted evidence can be owner-fenced reclaimed, with prior history preserved. Logical sequence intents/attempts and physical request evidence remain distinct. Unsupported withdrawal cannot fabricate completion.

## Connection finalization
Verification jobs retain encrypted pending values and reservations when missing permission/capacity proves no call. Job-bound verify grants expire and never transfer to the newly connected generation. The ordinary queued/running cleanup remains 15 minutes.
New jobs stamp installation_protocol=2 and an original capture +15-minute custody deadline. Preparation creates an account-local fence and no usable new session. Installation atomically matches that fence, original/prospective generations, owner and server $$NOW; completion rejects a custody-expired latch and checks server time again. Pending verification grants and physical preflight cannot outlive custody. A worker that lost the job/fence cannot activate cached credentials.
Unknown credential writes retain generation, IP lease, slot, lock and repair evidence. Grants reject prepared-running, finalizing and unfinished repairing jobs. A 60-second cleanup schedule operates with live flags disabled, scrubs overdue pending values, closes exact account fences and quarantines conflicts. Paid expiry also closes fences. Unresolved jobs omit TTL-indexed created_at until terminal cleanup completes.
Private drained repair can retain only the exact existing installed session or stop/scrub its exact generation. Possibly installed and unfenced legacy assets remain bound; only proven never-installed, job-owned new reservations release. Saved database repair is idempotent and cannot resend, restore pending credentials, regrant execution or resume campaigns. An unfinished retain decision can be explicitly stopped with a fresh digest/drain and retained audit history. The deadline plus available-worker cleanup objective is not guaranteed offline deletion or cached process-memory erasure.

## Content and outcome evidence
Local: exact content review binds tenant, sender/generation, source, recipient, enrollment, sequence version/digest, node, campaign revision and policy. Decisions have an identified reviewer, revision fence and 24-hour expiry; LinkedIn transport checks captured arguments and the final approval CAS. Email performs the final approved MIME comparison and approval CAS at its provider boundary. Source/resource-specific permissions bind the captured mailbox or finder credential generation. Received provider outcomes can repair their original operation/intent/task without HTTP or automatic campaign resume; email repair preserves the original acceptance time for inbound matching. Cached encrypted voice bytes/digest are reviewed and reused. Human playback acknowledgement is an assertion, not observed listening.
Outcome reconciliation remains a separate human assertion, distinct from content approval and provider observation. Manual jobs use awaiting_approval/queued/preparing/in_flight/unknown_outcome/projection_pending/resolving/resolved/completed/cancelled states and separate like/comment/reply stage evidence. Broker payloads contain references only. Matching receipts repair reporting without transport; completed/cancelled cleanup is idempotent and owner/token/target-fenced. Inbox reply slots and shared thread_revision prevent concurrent replies and stale sync projection. Unknown outcomes remain held until private drained review. Human assertion becomes human_confirmed, never provider_accepted or a synthetic response receipt, inbox message or verified engagement timestamp. Pending remainder stages cancel, and permission is revoked before token/owner cleanup. Saved repairs resume without HTTP. Due/publish/recovery timestamps are separate and ordered for fairness.
HTTP 200/URN means only the verified provider contract it supports. Distinguish request_attempted, provider_accepted, observed_sent, observed_delivered and human_assertion. Do not invent delivery/read proof.
The integration event outbox is separate from execution dispatch. Participating LinkedIn/mailbox reply callbacks now couple state/event writes in the same suppression transaction with idempotent event upserts. Other callers require their own shared transaction or recoverable event marker; optional session support is not proof all callers use it.

## Credential custody and workload identity
Opt-in KMS/AES-GCM custody is local for LinkedIn cookies (eleventh slice), managed IPRoyal passwords (twelfth) mailbox/OAuth/Hunter material (thirteenth) and OAuth application secrets (sixteenth), with unique nonces, authenticated caller context, pinned key/workload identity and drained installed-credential migration. Default custody remains legacy Fernet. Scoped Studio content (seventeenth) and ElevenLabs application-key custody (eighteenth) are also local. Older campaign artifacts/other shared-secret families, deployed IAM, memory/process isolation and remaining provider custody are still targets. Application config checks are process-local and require drained fleet cutover.
KMS encryption context and local authenticated context must bind canonical tenant/sender/version identity. Never hash ambiguous raw concatenation.
IMDSv2 hop limit 2 permits metadata responses through container hops; it does not provide KMS network connectivity or separate per-container IAM roles. Specify required role permissions and metadata isolation. [AWS metadata configuration](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/configuring-instance-metadata-options.html).
Broker payloads/logs/errors must be secret-free. Validate existing transport exception sanitization rather than inferring it from encryption.

## Local LinkedIn credential custody
Opt-in OUTREACH_CREDENTIAL_CUSTODY_MODE=kms_v1 binds pending/installed cookie envelopes to independently supplied workspace, sender, generation, purpose and environment. Async consumers reject plaintext/Fernet/mock/context swaps in KMS mode. No key-service call occurs inside Mongo retries. A configured exact temporary role and key ARN are checked; real AWS policies and container isolation remain unverified.
Private stopped/drained migration accepts strictly decryptable legacy Fernet rows, preserves generation/latched permission, invalidates inbox coverage and atomically saves a receipt. Pending storage rechecks paid/lock/erasure authorities; ambiguous acknowledgements retain job/resources. Legacy remains the default until cutover. Environment binding is not restore execution-epoch fencing. The twelfth slice below extends custody to managed IPRoyal passwords; the thirteenth extends mailbox/finder custody. ## Egress and SSRF topology
Target default deny must specify allowed database/broker/DNS/proxy/control routes and IPv4/IPv6 firewall behavior.
Direct LinkedIn transport must fail when the assigned proxy is unavailable; no direct-host fallback.
Webhook workers resolve and pin permitted public destinations, block local/link-local/metadata ranges including IPv6, and reject unsafe redirects/rebinding.
Separate general external API access from the LinkedIn transport process. Test proxy disconnect, DNS behavior and metadata access in the deployment environment.

## Disaster recovery
A single-node replica set enables database features; it is not high availability.
Daily off-host snapshots do not establish PITR. Set recovery point/time objectives and provide continuous backup/oplog handling if PITR is required.
Restore starts with all execution stopped and establishes a new environment/execution epoch. Old broker tasks and pre-restore authorization cannot execute.
Possibly submitted/unknown restored work requires reconciliation; pending restored work requires explicit reauthorization under the new epoch.
Keep durable revocation/history outside assumptions that an old backup is current. A restored_from_backup boolean alone is insufficient.
Validate with an isolated restore drill, not merely backup-success logs.

## Offline campaign voice preparation
Local tenth slice: explicit Prepare persists a policy/context-bound job; media workers make one bounded paid TTS call after a durable generating marker and daily workspace budget reservation. Final owner/context checks commit encrypted PCM WAV, digest/generation identity, pending review and receipt together. HTTP stays outside transaction retries. Missing receipts remain held without replay; saved preparation receipts reuse exact bytes. Review and sequence execution never generate audio.
The policy permits 1,000 finished script characters, 60 seconds of mono 16-bit/16 kHz PCM, and 20 clips / 20,000 characters per workspace per UTC day. Recordings expire after 24 hours; new generation identity requires fresh review even for identical bytes. Current artifact ownership and exact captured approval are rechecked before transport, including recipient/context changes with prior approvals for both choices. Erasure scrubs script/audio and retains minimal unknown generation evidence without TTL; stopped-work recovery changes only bounded scheduling metadata and cannot reopen the workspace.

## Account/workspace erasure and retained authority
Deletion persists a pending user and all actually owned workspace IDs before generic cleanup. The selected shared workspace is not ownership. Legacy private user-ID scopes are included only after proven ownership; capacity/unknown-collection failures remain pending. All tenants, including empty ones, await an identified operator's full writer drain and current inspection digest. Stop and bounded database-only cleanup share the stable workspace guard; secrets are scrubbed before content purge. Fresh reviewed retries revisit partial batches and recheck unexpected late rows. Cached credentials and older/raw writers require actual operational drain.
Minimal unresolved submission, known receipt, unfinished connection cleanup, financial and provider-term references may remain under explicit retention review. Known queued/accepted/completed work is not relabeled uncertain. Sanitized IP leases remain tenant-bound until current owned-asset expiry is independently verified; no provider cancellation or auto-renewal is implied. The closed workspace guard, Firebase UID digest and invoice/term binding digest have no TTL or reopening/reuse path. Digests are pseudonymous exclusions, not a legal retention or anonymization claim. Other owners' shared business data is preserved.
The durable account retry publisher and external cleanup retain pending users/references on failure. Customer status/copy does not claim universal immediate erasure or completed deletion on failed/unknown lookups. Backups, remote copies, whole-product data coverage, legal retention decisions and live provider/SDK behavior remain separate. Procedure and evidence: [Erasure and retention](UNRAVLER_IO_ERASURE_AND_RETENTION_RELEASE.md).

## Local managed proxy custody and orphan storage repair
Managed IPRoyal password custody is locally implemented in the opt-in `kms_v1` mode. Its authenticated context binds workspace, canonical asset ID, credential generation, transport metadata, purpose and environment. Sender ownership remains a separate one-sender lease and final authorization check. Imported inventory and embedded sender copies retain custody metadata; KMS mode refuses unscoped legacy assets. At the twelfth-slice boundary, mailbox/finder/voice/shared-secret custody, Webshare provisioning and actual workload IAM remained separate; the thirteenth slice below supersedes the mailbox/finder scope.
Each transport opens the proxy before authorization and captures the exact encrypted asset plus actual URL from the same snapshot. Mongo authorization compares that prepared binding against the current sender and inventory without KMS calls; replacements, workspace swaps and stale generations deny transport. Drained migration updates a managed asset and its proven sender aliases with an atomic metadata receipt, preserving leases, installed cookie generation and stopped permission. A saved receipt retries without key calls or automatic resume.
New connection locks retain a reference-only base-account/resource proof before attempting pending insertion. A private, all-writer-drained, live-disabled stop can close an absent job only when that proof still matches and no verification/installation evidence exists. It atomically stops permission, saves a permanent reference-only closure and removes only job-owned unused reservations/lock. Existing reconnect credentials and reused leases/slots remain held; older ambiguous locks, changed accounts, physical evidence or a now-present job require separate review. The closure omits TTL-indexed `created_at`; late insertion cannot reopen it. Workspace erasure can purge ordinary closure metadata only behind its permanent workspace exclusion. The connection dialog recognizes stopped terminal states. Procedure and evidence: [Proxy custody and storage repair](UNRAVLER_IO_PROXY_CUSTODY_AND_STORAGE_REPAIR_RELEASE.md).
