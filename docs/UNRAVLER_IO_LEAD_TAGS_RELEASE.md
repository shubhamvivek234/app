# Unravler.io v2.65 — Lead tags and reviewed follow-up drafts

Updated: 2026-10-14 IST, corrected v2.65.1 reverification. Local implementation only; not committed or deployed.

## Result

Leads, campaign lead profiles, Inbox, Settings and CSV export now share workspace-scoped lead-tag definitions with immutable IDs. Names and colors can change without rewriting lead assignments. A lead's assignments belong to that CRM enrollment record; this is not a new canonical-person database. A follow-up draft inherits the reviewed assignments and contact aliases at creation, not future edits to the original enrollment.

Leads supports tag/untagged filters, visible badges, selection on the current page, atomic bulk add/remove, and filtered CSV export. Settings → Lead tags and the Leads tag manager support create, rename, recolor and archive. Profiles opened from Leads or a campaign support individual assignment/removal and Do-Not-Contact. Inbox uses the linked CRM lead's assignments and has a tag filter. Unlinked conversations cannot silently create an independent lead-tag authority.

Selected leads can be reviewed for a follow-up campaign. Previously contacted leads are excluded by default; including them is explicit. Recorded replies, DNC, email suppression, duplicate identities, invalid URLs and withdrawal cooldowns remain exclusions. Saving rechecks the selection and decisions inside the transaction; a changed review returns a conflict. The new campaign is a draft with no assigned senders, sequence authorization or execution permission. Configuration, content review, paid/live/resource checks and launch remain separate.

## Storage and mutation contract

- `outreach_lead_tags` holds `id`, scalar `workspace_id`, normalized/display name, color, strict revision and timestamps. Names use NFKC normalization, collapsed whitespace and case folding. Archived names stay reserved. The workspace limit is 500 total definitions, including archived definitions.
- `outreach_leads.tag_ids` and `tag_revision` hold assignments. At most 50 IDs may be assigned, including archived IDs; archived assignments appear as removable controls in the profile. Archive hides active badges/filter/export names while preserving the assignment until explicitly removed and retaining the archived definition row/revision. Rename/recolor overwrite earlier values; there is no complete tag-edit audit log.
- Create/edit/archive, single/bulk assignments, legacy import, DNC and follow-up draft creation use the existing workspace suppression guard and snapshot/majority transaction. They reject a closed erasure workspace and have no standalone Mongo write fallback. Bulk selection is limited to 200 exact IDs and is all-or-nothing. Exact one-record-per-requested-ID validation rejects duplicate historical IDs rather than substituting them for missing selections. Assignment writes bind captured native IDs and original assignment/revision presence. Idempotent assignment requests do not increase the revision; stale single-lead or definition revisions are rejected.
- Required definition identity/name indexes fail cutover on inconsistency; lead tag and Inbox lead-link indexes support reads. The new collection is included in workspace erasure. Scalar workspace/resource queries reject array aliases in the new tag and selection operations.
- Lead tag writes require `lead:update`; reads require `lead:read`. Draft creation requires both `lead:create` and `campaign:create` in the same resolved actor/workspace context. A tag never changes pause, reply, consent, paid access, sender readiness, content approval, restore epoch or execution authorization.

## Older Inbox labels

Reads never seed definitions or rewrite old labels. Existing conversation strings remain visible as legacy labels. Settings offers an explicit, resumable import bounded by both 100 conversations and 100 labels per request, ordered by thread ID. Definitions are read once and each changed lead receives one assignment write per conversation. A dense 100-conversation × 50-label fixture completes in 50 resumable batches; the earlier per-label nested loop timed out without progress. Linked, well-formed labels become canonical assignments; original names/link/time are retained in `legacy_tag_migration`. Unlinked, ambiguous, malformed, archived-name-conflicting or over-capacity cases remain untouched for review. The last batch reports skipped counts; it is not a complete legacy repair system or a latency guarantee under arbitrary database/network load.

Deploy the backend and frontend contract together and drain old tag writers before running import. The old Inbox URLs now expose canonical tags; mutation requests use tag ID, explicit add/remove and revision. Older name-toggle clients need the new UI. No production migration was run during this implementation.

## Suppression and draft recovery

DNC controls save each current and original URL, email, member URN, secondary LinkedIn URN, Sales Navigator URN and explicit vanity alias independently. URL/member precedence cannot discard another populated alias. Compound matching retains independent current handles and secondary URNs alongside saved identifiers. A copied enrollment preserves these reviewed fields; later DNC evidence against any retained alias still matches it. Unknown future aliases are not automatically synchronized between enrollment records.

The follow-up review digest binds source identity/contact/tag/status/email-policy fields, admission decisions and a native BSON-encoded ID digest. ObjectId/string and int32/int64 collisions cannot preserve an old review; recreating an identical record with the same ID and facts is not independently detectable. Stored opt-outs/exclusions across matching enrollments block admission. Copies retain email verification, source URLs and original found/verified timestamps; invalid/unknown/accept-all/disposable verification cannot disappear during copying. Reply exclusion here uses lead reply flags/status/timestamps across matching enrollment identities; it is not a census or authenticated reconciliation of every Inbox/provider record. Reply matching keeps both candidate identity predicates and reply predicates, rather than replacing the identity query with all workspace reply history. The existing importer performs mandatory DNC/email/withdrawal checks again during commit, and execution retains its separate reply-stop/freshness checks. Final email dispatch currently checks the current email and stored negative flags; global propagation of later replies/suppressions across every enrollment and saved email alias remains an existing open gap. DNC compound matching does not establish that broader reply guarantee.

Draft campaign identity is deterministically hashed from workspace, actor and request ID; the campaign retains a payload digest, and enrolled-lead metadata retains the original request ID. Repeating the same request returns the existing campaign reference, its current name and the original imported count without another enrollment; it is not a frozen original response or current campaign-status report. Changing the payload conflicts. A separate authenticated `GET /leads/selection/context` supplies the opaque actor/workspace recovery scope without requiring surviving source leads. Draft POSTs require that exact scope; workspace/account changes return a nonterminal 403 before writes. Shared authentication can legitimately bootstrap another personal workspace, which cannot authorize a stale-workspace request.

The frontend stores unresolved references in tab-local session storage before submission and recovers them before attempting another source preview, including after source deletion. Up to ten scopes and 100,000 serialized characters are admitted before a write; exceeding capacity, corrupt data or storage failure preserves existing data and blocks another submission. Older correctly keyed references gain the same scope field without changing their request identity. Confirmed success clears it; conflict/deleted-draft terminal responses clear it and require another review. Clearing browser storage or losing the browser session still loses this client recovery reference; inspect saved campaigns before starting a new request after such a loss.

Lead refreshes admit only the latest current-filter response, including transports that ignore abort; completed bulk mutations refresh the current filter. Tag inventory errors have dedicated visible retry states and cannot be cleared by successful lead loading. Inbox detail/tag reads reject ambiguous linked identities and array resource/workspace aliases. Malformed or orphan CSV assignments emit `Unavailable: tag assignments require review` rather than silently exporting blank tags or failing after the CSV header; archived valid assignments remain hidden.
