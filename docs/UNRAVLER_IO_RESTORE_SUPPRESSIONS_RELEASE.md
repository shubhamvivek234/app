# Unravler.io v2.37 — selected recipient suppression restore

Date: 2026-10-09. Local, uncommitted and undeployed. Foundations through v2.22 remain at `04ca28b5d1dd7bd213ea67e951970e19fd93bdf3`; all earlier local work remains intact.

## Result and scope

A private controller can reapply selected original Do-Not-Contact and email suppression facts lost by an older database backup. It uses existing recipient-block collections and matching rules, under the matching prepared stopped restore epoch. It creates no inbox message, reply event, reply counter, freshness marker, positive permission or campaign resume. A source email block whose original reason was a reply restores only the negative block; it does not reconstruct that reply or its attribution.

This is selected negative reconciliation. It does not prove complete suppression/reply coverage, authentic source provenance, consent, identity ownership, financial/provider reconciliation, production restoration or readiness to activate. The exact byte digest binds the reviewed artifact; origin and storage outside backups remain operator responsibilities. Unlike the v2.36 deletion-hash manifest, this artifact contains private recipient identifiers and original times and requires private handling.

## Selected source and strict input

Export selects 1–100 original tenant-scoped DNC/email row references, with at most 100 expanded facts. String IDs are supported; a 24-hex reference also checks its native ObjectId form. Missing, ambiguous native/string matches, duplicate selected references or imported `restore_provenance` rows deny. Majority reads establish individual retained facts, not one atomic snapshot or a complete inventory. Source export requires an all-writer/cache drain assertion and majority closure checks before and after reads. The drain is not detected, and a raw/cache or post-check/file-write race remains outside this protocol.

Each fact contains exactly `kind`, canonical `field`/`value`, original UTC millisecond `blocked_at` and a hashed original record reference. The manifest adds version 1 and the target workspace-guard digest. It contains no reason, message, reply payload, owner, cookie, key or credential. DNC export preserves both saved `identifiers` and current flat aliases, including `linkedin_urn`; identical field/value occurrences within one row deduplicate. Independent overlapping source facts deny rather than silently choosing provenance. Supported canonical identities are normalized bare/www LinkedIn profile URLs, lowercase vanity/email, recognized member/person URNs and bounded Sales Navigator IDs/URNs. Unsupported legacy values require separate review, never permissive reinterpretation.

Import bounds input to 65,536 bytes and 100 distinct facts. Duplicate/unknown JSON fields, boolean/unsupported version, nonfinite values, malformed UTF-8, unsupported kind/identity, nonnative/unproven/future dates, incorrect scope and over-capacity sources deny. Parsed facts are immutable. Byte and normalized-fact digests bind inspection and the permanent journal.

The CLI reuses the verified v2.36 file helpers: exclusive 0600 export in an owned private directory, no overwrite, inode-owned partial cleanup, bounded stdin or owned private regular input with no symlink/hardlink and changed-read denial. Console output contains counts/digests, never recipient identities, source references or the manifest. Argument/runtime failures are sanitized. The manifest is read before connecting to the target database.

## Stopped transaction and retries

Inspect/import require the matching prepared stopped v2.35 epoch and all five execution/health flags false. Apply additionally requires exact source/evidence/operator/inspection digests and an all-writer/cache drain assertion. Both inspect and apply deny closed workspaces, including saved retries, because recipient data must not be recreated after erasure. Unlike v2.36 digest-only deletion exclusions, this importer never bypasses tenant closure.

The existing workspace suppression guard orders participating writes. A snapshot/majority transaction checks closure and fences the exact epoch root/journal/guard and existing selected target rows. No HTTP, key opening or provider call occurs. Email uses the existing workspace/email identity and rejects more than one matching row. DNC uses a dedicated deterministic workspace/field/value identity; its exact single saved alias and restore provenance must match, with no changed flat aliases. Original ordinary DNC rows are untouched.

Only missing facts are installed with `$setOnInsert`, preserving original times. Existing email blocks, installed DNC dates and other metadata remain intact; ordinary authority fence counters may advance. A generic restored-block reason avoids inventing the original reply/opt-out narrative. No lead, thread, event, KPI, inbox coverage, consent, credential, physical owner/token, budget, asset, lease or execution grant is changed. Original uncertain/received work remains held by the stopped epoch.

Readback proves every selected target block before inserting one permanent metadata-only source journal. Concurrent and saved retries require the same review hashes, matching current epoch, open tenant and all selected semantic exclusions still present. Removed/changed blocks cannot be hidden behind an old receipt. Captured epoch policy and flags are checked after the final awaited journal/read step; an observed change rolls back all writes. Commit can follow the last process-local check. Raw/older writers, undrained cached decisions and fleet/kernel enforcement remain outside the guarantee.

Evidence TTL removal for the source journal, DNC and email suppression collections precedes strict index builds. The unique `(workspace_id, execution_epoch, source_digest)` journal index and strict unique workspace/email index deny conflicts or duplicate cutover data. Erasure purges imported recipient facts and the journal, preserves only hashed review provenance and retains its permanent workspace closure. Erasure cannot turn a receipt into permission to recreate the data. Actual standalone Mongo denies without an application fallback.

## Private procedure

On the trusted source, identify the original DNC/email record IDs. Drain all writers and caches. Run `python -m outreach.ops.restore_suppressions export --workspace WORKSPACE --dnc-record ORIGINAL_ID --email-record ORIGINAL_ID --output-file PRIVATE_FILE --all-writers-and-caches-drained`; repeat either record option as needed and omit an unused kind. The directory must be owned and private. Keep the artifact and independently established provenance outside the database/configuration backup; the application cannot verify that location.

On an isolated open restored target, keep all five flags disabled and writers/caches drained, and prepare the stopped v2.35 epoch. Run `python -m outreach.ops.restore_suppressions inspect --workspace WORKSPACE --manifest-file PRIVATE_FILE` (or `--manifest-stdin`). Review exact digest/counts, then apply the same source with `apply`, `--operator`, `--source-digest`, `--evidence-digest`, `--review-digest` and `--all-writers-and-caches-drained`. Retain original review digests for lost-acknowledgement retries. No recipient, cookie, UID, key, grant, activation or replay arguments are accepted. Keep execution stopped afterward.
