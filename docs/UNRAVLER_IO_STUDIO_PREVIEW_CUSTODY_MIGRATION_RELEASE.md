# Completed Studio preview custody conversion — v2.32

Updated: 2026-10-08. Status: locally implemented and verified. Uncommitted and not deployed.

## Result and eligibility

The private stopped maintenance workflow converts an existing, unexpired, completed Voice Studio preview result from strict-Fernet storage to the existing scoped AES-GCM/KMS Studio result envelope. It preserves the original audio, owner, payload binding, received receipt, paid budgets, job configuration and exact expiry. It performs no synthesis, provider operation, source adoption, consent change, playback activation or expiry extension. Normal Studio consumers gain no legacy fallback.

Eligible jobs must retain completed preview status, a non-mutation marker, bounded original actor/owner/voice references and character count, exact SHA-256 job/payload/configuration/profile/source identities and only the recognized preview-job fields. Pending work, retained input blobs, alternate plaintext/audio fields, malformed or unknown metadata, missing/expired content and incomplete/unknown receipts deny. The received receipt contains only its native timestamp and audio digest. Original created/possible/received/updated/authorization/lease/expiry dates must be native BSON-millisecond timestamps with consistent ordering, an expired original worker lease and unexpired result. Recognition accepts at most the original 24-hour cache period plus a bounded 60-second interval for original post-receipt storage; conversion never adds that interval or replaces the retained expiry.

The current local profile must still identify the original voice/resource/source and have no active Studio slot. Its full snapshot is fenced, but its consent, revision, assignments, review hold and status remain untouched, including revoked consent. The original job's profile/configuration hashes are preserved as historical bindings, rather than relabelled as current permission. No current vendor-key opening, same-key source adoption or remote ownership attestation is performed.

Strict legacy opening authenticates the original workspace/job/payload/result-purpose scope inside the Fernet wrapper, rejects duplicate/unknown envelope fields and verifies bounded actual PCM WAV bytes against the original received audio digest. This encrypted context supplies the independent original tenant/job binding. The original preview script was already scrubbed by the producer; this workflow does not reconstruct it, infer a new script or invent a new provider receipt.

## Review and two transactions

`inspect` returns bounded workspace/job references, an exact normalized digest, blocker names, affected authority counts and `activation_allowed=false`. It captures the original job/profile, permanent conversion history, workspace closure, complete destination custody-policy digest and bounded workspace writer authorities. Migration requires all four outreach/integration/Voice Studio/voice-preparation gates off, scoped destination configuration, identified operator, separate SHA-256 evidence, exact inspection digest and explicit all-workspace-writer/cache drain acknowledgement. Drain is operator asserted; no actual fleet/cache inspection is claimed. Each authority collection is limited to 100 rows; ambiguous identity, active/unproven sender leases, pending Studio calls and unrecovered campaign generation deny.

A snapshot/majority workspace-guard preflight fences the source and authority basis, pauses workspace senders and active/warming campaigns, disables auto-launch, advances campaign authorization revisions, latches execution permissions and cancels known queued campaign recordings. Unknown physical owners/tokens/leases, paid budgets, original preview receipt/configuration and profile consent remain intact. Its post-stop snapshot must still contain the same original job/profile. Actual standalone Mongo denies before opening or key work; there is no fallback.

The stop commits before opening audio. Complete policy, disabled gates and original result expiry are rechecked after commit, after awaited legacy opening, after awaited scoped sealing and after all final awaited database readbacks. Opening/wrapping occur outside Mongo. The existing Studio envelope uses a per-blob AES-GCM data key wrapped under the distinct `voice_studio_key` purpose, workspace, the fixed `voice-studio-result` resource, original job ID as generation, result purpose and environment; its authenticated data retains the original payload scope. A changed sealing-job identity or malformed returned format denies installation.

The final snapshot/majority transaction revalidates the exact post-stop inspection, changes **only `result_enc`** on the full original job and atomically inserts its permanent metadata journal. It verifies the exact installed job. The final pure policy/gate/expiry check follows awaited receipt/readback work immediately before callback completion. Commit can follow; these are process-local checks, not fleet/clock consensus or kernel/socket enforcement.

Final ciphertext/journal installation is atomic, while the stop is an earlier separate transaction. Failed opening/wrapping/install leaves the original preview and committed paused authority. Lost preflight acknowledgement opens no audio. Without a saved receipt, preserve source/evidence and inspect again because authority changes alter the original inspection digest; do not alter expiry or enable flags to force a stale review through.

## Exact retries, erasure and playback limits

Request identity binds workspace/job/original inspection, with exact operator/evidence binding. Ordinary or guarded concurrently saved exact receipts precede original source opening, wrapping, installation and repeated stopping. Lost final acknowledgement resolves through that receipt. Different review/operator/evidence cannot reuse it. Exact retries report historical completion, current-job match, destination-policy match and `activation_allowed=false`; they do not decrypt audio, grant current playback or revive removed content. Competing callers that both passed preflight may each wrap once; exactly-once KMS billing is not promised.

The TTL-free `voice_studio_result` journal uses the existing credential-migration collection. It contains original-job/material/generation/operator/policy hashes, evidence/audio digest, original received/expiry timestamps and `strict_fernet_studio_result_conversion` provenance, with no audio, ciphertext, script, raw owner, raw operator or cookie. Strict partial unique workspace/job indexing follows retention-first startup; conflicting history fails rather than being ignored. No new blob collection, API, UI, broker workflow or recording lifetime is added.

The existing expiry scrubber continues removing only expired result content while retaining job/receipt identity. A concurrent scrub/replacement cannot be overwritten or recreated by conversion. Account erasure retains minimal hashed `voice_studio_result_custody_migration` provenance and the existing original submission evidence, while purging ordinary conversion/job content. Permanent closed tenants cannot reinstall after purge. Backup, legal retention and remote vendor deletion remain separate.

Conversion preserves storage custody for the remaining original cache lifetime. **It does not rewrite the legacy job configuration to the new custody configuration.** Existing preview checks still require current paid/member/profile/consent/configuration authority, and changed configuration can make this historical preview unavailable for playback. A separately authorized new preview may be needed; this workflow never resends the original job or invents current approval. Queued/incomplete input, unknown/held provider outcomes, older synchronous samples and unproven/expired previews are outside its conversion scope. Participating guards do not protect against arbitrary raw history alteration or an undrained older fleet.

Implementation: `outreach/core/voice_studio_migration.py`, private `outreach/ops/voice_studio_migration.py`, strict partial index in the existing recording-migration index helper and minimal retention in `outreach/core/erasure.py`. Existing Studio crypto/producer/consumer code is unchanged.

## Private procedure

Independently retain and review the original receipt/job/profile evidence. Keep all four gates disabled, configure scoped destination custody and pause/drain all workspace writers/caches. Inspect the existing job on the trusted backend host:

```text
python -m outreach.ops.voice_studio_migration inspect --workspace WORKSPACE --job ORIGINAL_JOB_SHA256
```

Review every blocker and preserve the exact digest. Only an eligible original result may proceed:

```text
python -m outreach.ops.voice_studio_migration migrate --workspace WORKSPACE --job ORIGINAL_JOB_SHA256 --operator OPERATOR --evidence-digest REVIEW_EVIDENCE_SHA256 --review-digest INSPECTION_DIGEST --workers-drained I_PAUSED_AND_DRAINED_ALL_WORKSPACE_WRITERS_AND_CACHES
```

References/digests must contain no secrets. There are no audio, password, script, source, generation or expiry inputs. Parser/runtime errors are sanitized; the Mongo client closes after database-selection failure. Keep original evidence and metadata receipts, and inspect mismatches separately. The command installs no configuration and supplies no activation. See the [operator guide](OUTREACH_PROXY_PROVIDERS.md).
