## Connection recovery contract

[Sender recovery](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/sender_recovery.py) requires a strict scalar workspace and sender identity, an existing `checkpoint`/`checkpoint_detected` connection, an original recognized cooldown reason (`rate_limited_429`, `commercial_limit` or `proxy_unhealthy`) and a proven elapsed cooldown. Session-expired, CAPTCHA/999, malformed/missing cooldown and other unproven states require reconnection or operator review. `force=true` is retained in the API schema for compatibility but always rejected; it cannot override the platform cooldown. A present installation fence must be closed with `verified_install` completion; this does not authenticate older unfenced installation history.

Before opening keys, recovery checks the open workspace, positive restore admission, active paid term, enabled live policy, current proxy inventory/provider expiry, exact embedded proxy binding, same-workspace sender lease and slot, and selected unresolved sender work. Array workspace/payment/lease/slot aliases cannot establish ownership. An installed restore epoch remains stopped; this endpoint cannot perform new-epoch activation.

Selected sender authorities must be unique and canonical, idle, owner/token-free, generation-matched and unlatched. An existing permission must be proven expired with its original bounded lifetime. A still-valid permission, latch, physical owner, armed health control or selected unresolved physical/intent/task/manual/connection work requires operator review. This prevents recovery from implicitly making an existing live permission usable. The endpoint neither clears these holds nor adopts their work. This is a selected current-record check, not a complete census of every legacy/raw writer or external operation.

Cookie and proxy password records require recognized encrypted storage. Session and proxy opening run outside MongoDB callbacks with five-second caller timeouts. Usable bounded cookie/JSESSION values and authenticated proxy credentials are required; empty, malformed, mock/test sessions, corrupt/wrong-key encrypted session values and unusable proxy credentials deny recovery. Legacy plaintext session fallback cannot establish recovery proof. Default legacy custody is exercised with disposable synthetic keys; actual KMS access, IAM and provider behavior were not tested. Caller cancellation propagates without changing the sender state. These application timeouts do not establish remote cancellation or erase a provider's possible request.

The final snapshot/majority workspace-guard transaction rereads and writes the original sender identity and existing matching authorities. It compares the complete captured account basis, repeats the resource/hold checks, and checks process-local custody/epoch/live policy and paid/provider deadlines before and after the conditional status write. Concurrent erasure, replacement, credential/resource/term changes and tested policy changes deny or roll back recovery. The endpoint changes only connection status and clears its original stop/cooldown/error fields. Credentials, generations, proxy assignment and existing permission content remain intact; authority read-fence counters may advance.

The last pure policy/deadline check precedes transaction commit. A term can expire or process configuration can change after that check; this is not an atomic clock or fleet-policy guarantee. Later launch and physical dispatch revalidate their current authorities and deadlines before permitting work.

The response explicitly reports `tasks_resumed: 0`, `campaigns_resumed: false` and `execution_permission_granted: false`. Known eligibility failures return 409; transaction unavailability returns a sanitized retryable 503. A standalone database cannot complete the transition. A lost/unknown commit acknowledgement does not authorize replay or resume work; reload the account to inspect its current state. No request-idempotent recovery receipt or automatic retry is introduced.

An active connection is not a fresh provider health observation, a verified currently valid remote session, campaign readiness or execution authorization. Launch and workers retain their own final gates. Permission admission uses the existing resolved account-connect role context; this slice does not claim universal transactional serialization of role revocation.

## Stop-handler workspace isolation

Review of the adjacent [circuit breaker](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/circuit_breaker.py) and [Safety Shield](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/safety_shield.py) found additional unscoped task/alternate-sender/campaign/event paths. Native tests inserted foreign same-ID parents first and reproduced foreign task/campaign effects before the repair.

Both stop helpers now require an explicit scalar workspace before any mutation. They scope sender/task/campaign queries to that workspace and pause pending/queued/scheduled tasks using either existing account field. The circuit breaker counts alternative senders in the same workspace, conditionally pauses the captured campaign and advances its authorization revision/pause reason. Outbox deduplication includes the workspace and cannot overwrite a foreign event sharing the same digest. These remain existing multiple-write stop workflows; this slice does not make the entire stop operation atomic, resumable or a complete authority-revocation protocol.
