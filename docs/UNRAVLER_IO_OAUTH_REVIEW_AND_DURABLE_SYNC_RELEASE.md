# Unravler.io — drained OAuth review and durable mailbox synchronization
Version: 2.16.0 | Updated: 2026-10-04 | Status: Local implementation; rollout and live-provider evidence pending

The fifteenth slice supplies a private stop-only OAuth review and replaces periodic provider polling with persisted sync jobs, reference-only publication, conservative physical-read evidence and recoverable cursor installation. Default custody remains `legacy_fernet`; live actions, mailbox/email and campaign generation retain their disabled configuration defaults. No commit, push, deployment, production grant, purchase or real AWS/provider call was made. Prior connection guarantees remain in the [fourteenth-slice report](UNRAVLER_IO_DURABLE_MAILBOX_CONNECTION_RELEASE.md).

## OAuth hold review

`OAuthHoldReview.inspect` returns status, blockers, impact counts and an exact snapshot digest, without code/PKCE, tokens, mailbox address or operator evidence. The snapshot includes the original job/owner/material, current mailbox, sender and permission authorities, bounded active connection/sync jobs, browser states and affected campaigns. A live worker lease, installed receipt, other active connection or capacity gap denies closure.

`stop` requires an identified operator, 20–2000 characters of evidence, exact digest, explicit all-mailbox-and-sender-writer drain assertion and disabled live actions. Its snapshot/majority workspace transaction writes applicable read-authority fences and revalidates the complete inspection. It latches sender permissions, pauses the sender and active/warming campaigns, invalidates campaign authorization revisions, scrubs the inspected mailbox credentials and pending code/PKCE, stops its sync jobs and removes only captured browser-state rows. It closes the active OAuth slot as `review_stopped` only after those stop transitions, in the same transaction.

The original exchange state/owner remain; an unknown grant stays unknown. The immutable review is `operator_local_stop`, explicitly `provider_revocation_verified=false`. The command makes no provider request, replays no code, installs no credentials, fabricates no receipt and grants no campaign or sender execution. Exact saved-review retries return their receipt and cannot scrub subsequently replaced credentials. Different actor/evidence/digest retries deny. Customer job lookup returns a static stopped-review reason, and browser polling ends on that status. Reactivation, new authorization and any provider-side grant revocation remain separate decisions.

## Durable mailbox sync

- The periodic selector persists one active workspace/sender job under the workspace guard before broker publication. Jobs bind mailbox/provider/connection generation, original cursor digest, custody policy/environment and a fixed coverage start/deadline. Reconnects preserve the existing history/delta cursor. A queued job has no bearer, raw provider request URL, message content or cursor token in its payload; broker messages contain only workspace/job references.
- Separate thirty-second publishers and recovery tasks use bounded fifty-row due scans. Two-minute exact worker ownership, a fixed ten-minute job deadline and at most five worker attempts prevent stale/replaced workers from continuing. Scheduling-only guard backoff rotates closed/disabled/unpaid prefixes without reopening erasure or broad-stale writes to replacement mailboxes. Selection retains bounded concurrency of five. Actual standalone MongoDB denies ownership before credential or HTTP work; no fallback exists.
- Each provider GET commits a `possible` read and an allowance charge in the same workspace transaction before HTTP. Captured job owner/basis, actual prepared bearer ciphertext/generation, paid sender, token expiry, pilot/custody policy and lease/deadline are revalidated. Captured deadlines and policy are checked synchronously after commit. Token refresh receives the exact sync-parent validator inside its possible-marker and installation transactions; stale workers cannot refresh before the read guard. Key operations and HTTP stay outside transaction retry callbacks.
- The pilot allowance is 1,000 possible reads per sender/UTC-day and 600 physical reads per job, with existing twenty-page/500-message parser bounds. Permit acknowledgement loss, local non-call denial and interrupted reads never refund counters. Saved responses are reused locally. An unsaved **read-only GET** may receive a new bounded physical attempt/charge; its original `possible` becomes `read_interrupted` rather than being erased or treated as a non-call. This permission does not apply to OAuth exchange/refresh, email delivery or other mutations.
- HTTP redirects are disabled. Requests ask for identity encoding and reject encoded responses before any decoder runs. Raw identity streaming content is capped at 2,000,000 bytes before the worker response buffer can exceed that bound, with a 25-second overall request timeout also bounded by captured deadlines. Response cache content is capped at 8,000,000 bytes per job. Request URLs/parameters are represented by digests; response bodies are encrypted and authenticated to workspace/sender/job/basis/request identity. Legacy Fernet has an authenticated embedded binding; opt-in KMS wraps a random AES-GCM content key under the distinct `mailbox_sync_key` purpose and environment context. The existing 32KiB credential limit remains unchanged. KMS uses the existing pinned workload/key adapter; no actual IAM evidence was collected.
- Receipt and job cache accounting commit together. Lost receipt acknowledgement can recover only the matching saved owner/request ciphertext. Missing receipt data remains interrupted evidence; reconnect, key failure or erasure cannot turn it into a received result. Fully cached recovery neither opens a mailbox bearer nor invokes token refresh. An initial Microsoft delta filter uses the immutable coverage timestamp across page recovery.
- All pages, message details and required DSNs must parse completely before cursor advancement. Missing required Gmail/Graph identity/sender/timestamp metadata, incomplete pages, excessive backlog or unattributed bounces leave the original cursor and stale send gate. Each message's suppression/lead/task/KPI/inbox/event/dedup changes and job projection progress share one guarded transaction. Partial failures roll back together; received caches and progress support retry without provider replay or double counting.
- Cursor change, mailbox healthy/fresh coverage and terminal job receipt commit atomically, with exact current owner, connection generation and original cursor revalidation. Lost completion acknowledgement recovers the local job receipt. Coverage freshness uses the original job start, not recovery/completion time. Older workers cannot project into, stale-mark or clean up a replacement mailbox. New inbound identities include stable provider/account identity while same-account reconnects preserve deduplication. Legacy raw-ID matches require proof through the original operation provider/sender address; ambiguous legacy identity blocks coverage for operator review.
- Completed jobs atomically scrub cached response ciphertext while retaining read status/digest/timestamps. Failed/stopped cache content is scrubbed by bounded, status/owner/basis-fenced guard-only cleanup after its fixed deadline; evidence has no TTL. Erasure scrubs active received caches, purges job/read/budget data and retains only minimal received/interrupted read evidence with `mutation=false`. Credential migration rejects active sync jobs. This is bounded logical cache cleanup; physical deleted-byte recovery, remote copies and backups are outside scope.

## Private operator procedure and cutover

Drain old/new API, OAuth, sync/refresh, beat/publish/recovery, sender/campaign/transport, paid-expiry, erasure and credential writers and their caches. An operator assertion is not a drain detector and cannot cancel already authorized remote work. Verify actual snapshot/majority transaction support. Keep live/generation flags disabled.

```bash
.venv/bin/python -m outreach.ops.pilot inspect-oauth-hold --workspace WORKSPACE_ID --job JOB_ID
.venv/bin/python -m outreach.ops.pilot stop-oauth-hold --workspace WORKSPACE_ID --job JOB_ID \
  --operator OPERATOR_ID --review-digest INSPECTION_DIGEST \
  --evidence 'Recorded evidence identifying the drained local authority review.' \
  --workers-drained I_PAUSED_AND_DRAINED_ALL_MAILBOX_AND_SENDER_WRITERS
```

Inspection reports whether the current mailbox will be scrubbed and how many campaigns will pause. Review that concrete impact before calling stop. Never delete a held job, reset its exchange state, invent provider revocation or clear an execution latch to bypass uncertain physical work. Review operates only on open workspaces; stopped tenants belong to drained erasure. There is no customer resolution endpoint.

The existing OAuth retention-first migration still runs before other index builds. Then strict mailbox workspace/sender uniqueness, active sync uniqueness, one received request-index receipt, physical-budget identity and due indexes must succeed. Conflicts/duplicates fail cutover; no index exception is ignored for these authorities. Sync job/read metadata has no TTL. Verify the additional `mailbox_sync_key` KMS purpose in actual deployment policy before opting into scoped response caches. Already removed historical data, unknown old cursors, raw database writers and restore epochs are not reconstructed by index creation.
