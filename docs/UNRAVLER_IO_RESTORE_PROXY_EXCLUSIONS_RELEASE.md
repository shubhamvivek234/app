## Result and limits

A private controller can restore selected permanent physical-IP binding digests lost by an older backup. Every imported digest blocks positive reuse. It restores no proxy inventory, credentials, sender lease, provider order, payment, ownership, paid term, grant or activation. Participating imports, reservations, readiness checks, physical LinkedIn dispatch, connection verification/installation and custody/lifecycle workflows now check these negative facts.

Original `account_proxy_ip_guards` record local reservation/assignment bindings. A guard may remain after failed preparation, key work or installation; it is not vendor ownership, payment, current availability or provider-term proof. The original key hashes the canonical public IPv4 under `managed-proxy-ip-v1`; the binding hashes workspace, local asset ID and provider. The manifest contains no raw IP or binding inputs; the controller does not reconstruct them. Deterministic IP hashes remain linkable: candidate IPv4 addresses can be enumerated/matched, so the artifact remains private. The workspace argument selects review/epoch/journal scope, not ownership of a global IP hash.

This is selected negative reconciliation. Individual majority reads and an asserted source drain do not prove an atomic, complete or authenticated source inventory. Exact-byte and normalized-fact digests bind reviewed integrity, not trust. Complete selection, source provenance and private storage outside backups remain operator responsibilities. Selected exclusions cannot authorize restored activation.

## Selected source and private artifact

Export accepts 1–100 distinct canonical SHA-256 global guard IDs and an all-writer/cache drain assertion. Every selected row must retain a canonical original binding digest and have no `restore_reuse_blocked` field. Missing, malformed or previously imported rows deny. There is no tenant inventory listing, automatic expansion, raw-IP lookup or inferred provider fact.

The strict version-1 manifest contains `workspace_guard_digest` and `ips` with exactly `ip_digest`/`binding_digest` pairs, bounded to 65,536 bytes. Unknown/duplicate fields, boolean/unsupported versions, duplicate hashes, malformed UTF-8, nonfinite values and capacity excess deny. Facts are sorted and frozen for review.

The CLI reuses v2.36 private file helpers unchanged: exclusive 0600 export in an owned private directory; bounded stdin or owned private regular input; overwrite/symlink/hardlink and changed-read denial; inode-owned partial cleanup. Import input is read before the database connection opens. Console output is bounded metadata, counts/digests and the requested workspace ID. Argument/runtime errors are sanitized; raw IP, provider material and manifest facts are not echoed.

## Stopped import and global ordering

Inspect/apply require the matching prepared stopped v2.35 epoch and all five execution/health flags false. Apply also requires exact source/operator/evidence/review digests and an all-writer/cache drain assertion. An already-closed target permits only these hash negatives while its matching stopped root exists; closure is never cleared. Full erasure removes that root and the workspace journal, so later import cannot bypass preparation or reopen the tenant.

The existing shared guard/snapshot/majority transaction fences root, guard and source journal. Each selected IP also touches a permanent global `account_proxy_ip_restore_fences` row before reading its original guard. Participating transactional negative checks touch that same row first, closing the cross-workspace race where an older backup lost the original guard entirely. Existing original guard rows receive same-session write fences too. A separate fence row may exist without an original guard; it supplies ordering, never an ownership binding.

Existing bindings must match exactly; malformed restore flags deny. Missing guards retain the original binding via setOnInsert; all selected guards receive `restore_reuse_blocked=true`. Readback proves every block before saving a permanent hashed journal. Exact saved retries revalidate original review hashes, current root and all current blocks. Concurrent/commit-then-raise simulated acknowledgement-loss retries preserve replacements and cannot use a saved journal to hide missing blocks. Conflicting first fence upserts may fail closed through `SuppressionUnavailable`; guaranteed automatic success on duplicate-key abort is not claimed. Observed final policy/flag changes roll back; commit may follow the last local check.

Retention-first TTL removal includes the new journal and global fence collection; original global IP guards were already retained. A strict unique `(workspace_id, execution_epoch, source_digest)` journal index precedes cutover. Erasure purges the workspace journal and retains minimal hash provenance; global guards and fences remain outside tenant purge, with no TTL or reopening path supplied.

## Positive-use boundaries

The negative helper requires a canonical IPv4; malformed/missing/hostname input denies. Loopback remains valid for existing isolated transport drills; this grants no network permission, and managed imports still require public IPv4. An absent guard is compatible only with the legacy negative check and supplies no positive ownership proof. Any `restore_reuse_blocked` field, including malformed false/null/string values, blocks positive use.

Managed IPRoyal/Webshare imports deny restored exclusions before sealing. New reservation and same-sender reconnect skip/deny blocked inventory while preserving retained leases. Sender readiness and physical request validation check both the actual embedded sender IP and a present inventory IP, so differing legacy copies cannot evade a negative. The final dispatch transaction participates in global fence ordering before transport factory admission; existing positive Webshare proof remains mandatory.

Connection verification performs guarded epoch/negative admission before proxy-key opening, again after preparation before health, and after profile/current-inventory reads before installed-session sealing. Final IPRoyal credential installation checks both hosts within the existing owner-fenced transaction; Webshare retains its stricter original binding protocol. Migration/adoption/lifecycle inspection blocks restored exclusions before key work; exact saved receipts preserve historical results while reporting `current_matches=false` for newly blocked resources. No block clears a receipt, uncertain call, physical token, budget, credential or lease.

These are local admission boundaries. They do not cancel a call already admitted, revoke an earlier committed installation, atomically order KMS/HTTP with MongoDB, prove fleet/cache drain or constrain older/raw tools. A block arriving after the last committed local admission can follow already-admitted key/network work; drains remain essential. Actual IAM, kernel/proxy-only egress, complete provider/financial facts and explicit restored activation remain separate work.

## Private procedure

On the trusted source, independently identify original global guard IDs and provenance; do not treat a guard as vendor ownership. Drain source writers/caches. Run `python -m outreach.ops.restore_proxy_exclusions export --workspace WORKSPACE --ip-digest DIGEST --output-file PRIVATE_FILE --all-writers-and-caches-drained`, repeating `--ip-digest` for selected hashes. Keep the owned private artifact and independent provenance outside backups; the CLI cannot verify that storage location.

On an isolated target, keep all five execution/health flags false, drain writers/caches and prepare the matching stopped epoch. Run `python -m outreach.ops.restore_proxy_exclusions inspect --workspace WORKSPACE --manifest-file PRIVATE_FILE` (or bounded `--manifest-stdin`). Review source/counts/exact digest. Apply that same source with `apply`, `--operator`, `--source-digest`, `--evidence-digest`, `--review-digest` and `--all-writers-and-caches-drained`. Keep the original digests for retries. No raw IP, password, asset restoration, lease grant, provider purchase or activation follows.
