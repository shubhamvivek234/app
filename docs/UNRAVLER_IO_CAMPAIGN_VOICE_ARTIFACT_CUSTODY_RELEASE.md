# Campaign voice artifact custody — v2.26

Updated: 2026-10-08. Status: locally implemented and verified; uncommitted and not deployed.

## Result and scope

Campaign recordings now have opt-in scoped storage and operation-local audio proofs across preparation, preview and dispatch. New KMS-mode WAVs use a fresh AES-GCM key wrapped through the existing pinned workload custody adapter. Default legacy Fernet storage remains compatible for valid bounded recordings. Voice generation remains offline on media workers; the executor loads the reviewed bytes and never synthesizes or retries a paid generation call.

This replaces the shared-format gap in the campaign artifact writer/consumer path. It does not migrate installed old ciphertext, establish vendor ownership, resolve an unknown generation outcome, migrate shared application keys, activate a sender or enable any flag. Studio input/result custody and ElevenLabs application-key custody retain their separate existing contracts.

## Storage and identity

The `va1:` envelope contains exactly a wrapped key, a 12-byte nonce and bounded authenticated ciphertext. Duplicate JSON fields, malformed fields, invalid encodings, wrong key scopes and excess sizes deny with sanitized errors. KMS context binds workspace, artifact identity, generation, `voice_artifact_key` purpose and environment. Authenticated audio metadata additionally includes the original binding digest, audio SHA-256, byte count, media type, sample rate, duration, preparation timestamp and expiry. Scoped timestamps use exact UTC BSON millisecond precision; naive UTC reads normalize to the same identity. The original context hash must equal the artifact ID.

Actual WAV parsing checks mono, 16-bit, 16kHz uncompressed PCM, decoded frame length and the existing 60-second maximum. Both scoped and legacy 60-second recordings round-trip. Scoped envelopes permit at most 2.7 million characters; legacy storage permits 3.5 million to accommodate its historical double Base64/Fernet expansion. Content never becomes plaintext database or broker storage. Scoped mode rejects old Fernet/plaintext without a fallback, and legacy mode cannot open a scoped recording.

A recording lives at most 24 hours from its preparation timestamp. Opening verifies the actual bytes against all stored media/digest facts, then rereads the current database row after awaited key access. A replaced generation, changed ciphertext, expiration, erasure scrub or mode/environment/workload configuration change denies returning the old audio. Python, SDK and crypto memory copies are not guaranteed zeroized; operation-local mutable key copies are cleared, while workers/caches still need actual fleet drain. Representation output hides prepared ciphertext and audio.

## Database and provider ordering

Queued preparation jobs capture a custody-policy digest alongside the application provider configuration. Missing scoped proof or changed policy stops before a paid generation marker, budget or provider call. Existing bounded legacy jobs retain compatibility. Pinned KMS configuration construction is metadata-only; it does not prove actual IAM or KMS health.

After the worker receives and validates generation output, key wrapping and audio sealing happen outside all retryable Mongo callbacks. The original guarded final transaction rechecks owner, unexpired lease, current tenant/lead/sender/profile/content authority, provider source and prepared-artifact integrity before database-only installation and pending review creation. An owner already expired at the final transaction's lease check is denied. That lease is checked at transaction entry; this slice does not add a synchronous lease deadline check after every subsequent await or commit. Generating ownership is not automatically reclaimed, and guard-ordered recovery still fences the original owner. A changed context discards output without creating a current review. A storage failure after a possible paid call leaves the original job held, retains its charged allowance and never makes a second generation call. A final projection failure rolls back the artifact/review; recovery retains the original interrupted paid-call hold without repeating key wrapping or generation. No new durable raw-audio receipt is added.

Prepared-job reuse and batch review preparation perform metadata/format checks in the guard transaction. They do not open KMS or prove decryptability; an unavailable/tampered recording still denies preview and dispatch. The API preview/current-review paths perform independent strict opens. Preview rejects an older approved generation even if a replacement has identical audio bytes. Playback acknowledgment remains a human assertion, not observed listening.

The sequence opens one clip outside authorization callbacks and passes its exact immutable-content proof through repeated review checks. The final snapshot/majority authority wrapper writes the original artifact row alongside the existing execution authorities and compares the complete captured storage identity; a replacement after snapshot read causes serialization/revalidation and denial. The captured recording expiry and pure policy/content checks are returned for the existing post-commit pre-call check. No KMS call occurs inside authority/suppression wrappers. The clip stays in the worker operation and is not serialized into a job, permission or request payload. Existing LinkedIn physical-request and unknown-outcome contracts remain; this slice adds no new socket/DNS checkpoint, delivery guarantee, kernel-egress proof or crash/redelivery claim.

Erasure continues scrubbing the single `audio_enc` field and marks the recording failed under the workspace guard. No second blob/key collection is introduced. Actual erasure during key opening denies returned audio; erasure during sealing prevents installation while retaining interrupted paid-job evidence. Existing artifact TTL and approval expiry remain unchanged; TTL cleanup timing is not an authorization clock.
