## Captured content and authority

`capture_snapshot` in [template_metadata_snapshots.py](/Users/shubham/Documents/Workspace/SocialEntangler/app/outreach/core/template_metadata_snapshots.py) requires a dedicated actor/UID/workspace snapshot scope plus the original public/native identity, revision and full BSON review digest. The shared guard/snapshot-majority transaction checks current sequence-update permission, unique native user/UID/member-or-owner authority and strict session-bound erasure/open-workspace observations. The exact current template must still exist and match that proof. The complete bounded recorded digest lineage must validate, contain its exact matching ordinary checkpoint and contain neither a deletion terminal nor a future revision. Missing checkpoints are not backfilled.

Capture writes guard/user-role authority counters and one immutable encrypted snapshot. It does not change the source template, advance a revision, append checkpoints, execute actions or write an operation receipt. Metadata capture is supported at the final JavaScript-safe revision. An absent legacy description holds instead of silently inventing empty text. Current viewers/clients cannot capture; another currently authorized editor may repeat a still-current capture while preserving the original ciphertext and attribution.

Only exact validated `name` and `description` are selected; extra source fields, graphs, credentials and Firebase UID fields are not copied. Allowed free text may itself contain sensitive information, so this is field exclusion rather than secret-content detection. Existing template metadata remains plaintext; this slice encrypts the additional retained copies only.

## Encryption, identity and repetition

The exact twelve-field stored envelope includes deterministic snapshot ID, contract/version/kind, workspace/public/native identity, revision/full-record hash, matching checkpoint ID, public capture actor, UTC millisecond timestamp and ciphertext. The nonempty canonical JSON plaintext contains only the full typed context and the two metadata fields. Existing Fernet encryption and strict decryption authenticate that envelope; legacy plaintext fallback is never used. No low-entropy plaintext metadata hash is stored. Stored-row bounds are checked before decryption; duplicate/extra JSON keys, bool/float numeric aliases and context transplants hold. Public-template/source binding is checked before sealing.

Missing/malformed keys, rotated keys that cannot decrypt retained rows, cipher corruption and malformed records hold without overwriting, repairing, logging plaintext or silently re-encrypting. Existing application key custody/rotation remains an operational dependency; no KMS/provider call or key provisioning occurs here. This does not supply cryptographic erasure or protection outside a rolled-back database/key backup.

Deterministic ID binds workspace/native identity/revision. A repeat under the same still-current proof validates every retained encrypted record against its matching checkpoint, compares current selected content, and returns the same minimal metadata-only result without rewriting ciphertext/audit bytes. That result exposes no captured text or ciphertext and grants no execution. An unknown acknowledgement returns sanitized503; an explicit repeat works only while original source proof remains current. This is not historical operation-result recovery after edits/deletion and introduces no automatic replay.

## Storage, retention and erasure

`outreach_template_metadata_snapshots` uses the same validated nonunique ascending `(workspace_id, identity_digest, revision, _id)` index definition in its own collection. Explicit administrative `prepare_storage` delegates to the shared extracted `prepare_index` helper; existing history preparation behavior stays unchanged. No startup or customer request installs indexes. Required definitions are observed before/after capture, with simple collation and a forced hint. Missing/conflicting definitions or any TTL index hold; nothing drops, repairs or evicts existing records. These DDL observations are not a global DDL fence.

At most1,001 returned wrappers inspect a1,000-snapshot identity cap. A2,000ms aggregation uses full-row BSON-size projection with a16KiB row limit and tiny size/null sentinels for oversized rows, including native IDs. ASCII ciphertext is bounded to14,000 characters before decryption. Accepted retained-plus-new BSON totals at most8MiB. The total check follows bounded projected loading; it is not a physical network/server byte or whole-transaction runtime guarantee. Every same-native candidate counts, including malformed/public-ID-drift rows. At capacity, an exact existing capture can be confirmed; a new capture holds without eviction.

Insertion requires exact BSON readback and strict decryption/content verification. Snapshot/authority writes roll back together on insertion/readback/index-drift failure. Existing guarded actual account/workspace erasure now includes the new collection even after source deletion; erased authority cannot capture again. Older erasure workers must be drained/replaced before any future activation. Other raw writers, backup retention, key custody and operational performance remain separate limits.
