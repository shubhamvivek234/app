# Unravler.io v2.66 — Search-source trust

Updated: 2026-10-14 IST. Bounded F0 implementation, local and uncommitted. No deployment or source activation.

## Result

User input can no longer select generated search prospects in production search code. Basic, Sales Navigator, Recruiter, connections and events collection are explicitly unavailable until source-specific filters, result schemas and access contracts are verified. CSV and pasted public LinkedIn `/in/` profile intake remain available. This deliberately closes an unverified capability; it does not claim a working full-filter search adapter.

The import modal reads the versioned server catalog, keeps unavailable/unreadable capabilities disabled and ignores stale responses from an earlier campaign. Saved jobs and staged rows remain inspectable. Their preview labels say saved/unverified, and enrollment is disabled. This preserves evidence without treating older generated or filter-incomplete rows as verified people.

## Input, response and collection contract

- `outreach/core/search_sources.py` recognizes only exact HTTPS `linkedin.com` or `www.linkedin.com` People-search paths with a bounded keyword-only query. It rejects credentials, ports, relative/lookalike hosts, fragments, malformed encoding, duplicate/unknown query keys, unsupported filters and keyword syntax that could alter the adapter query grammar. Only recognized non-audience `origin` values may be discarded; no audience filter is silently dropped.
- Parser recognition and collection availability are separate. Catalog contract version 1 reports every source unavailable, independently of live/mock flags. There is no new flag or seat-based bypass. The API denies new collection before entitlement/credential/provider preparation. An owned worker claim stops the old job with `search_source_review_required` before opening credentials; a stale lease cannot stop a replacement owner. Existing stopped/terminal rows are retained.
- The input-selected generator was removed from `search_people_entities`. Historical fixtures now live only in explicitly injected test code. A mock adapter refuses this search method; non-mock magic keywords use the transport spy and cannot synthesize results.
- The retained internal keyword transport has bounded paging, rejects redirects and conservatively checks response shapes, error/status wrappers, row field types and contradictory totals. An absent total remains unknown; observed zero is preserved; errors cannot become an invented zero or 1,000. These are internal contract tests with synthetic responses, not authenticated people/schema/filter/completeness proof. Broader source fidelity remains F3.

## Retained-provenance holds

Known search markers include non-null `import_job_id`/`staged_at`, staged state, `linkedin_search` source/metadata and an explicit review latch. Malformed non-null source/metadata/state shapes also remain held. Ordinary modeled null markers are allowed, so normal CSV intake is not disabled.

Guarded generic intake checks submitted markers before model normalization and directly queries known scoped IDs without a duplicate-ID lookup limit that could hide a held row. Reviewed follow-up selection projects retained markers before copying. Search commit and individual resume deny; private pause rejects staged/malformed state and binds its captured scalar/null/missing state. Public pause also cannot normalize a held row. Shared readiness, activation/assignment, early nonphysical sequence steps, current advancement/failure projections and final LinkedIn authorization/email-finder provider validation retain the hold. Resume and authority-changing recovery/reconciliation updates atomically exclude current source-review predicates, including an array that Mongo could otherwise match as its contained scalar.

Real reply, possible-reply and bounce writers preserve a permanent `search_source_review_required` marker on the same affected records before changing their state, inside the existing suppression transaction. The original identity filter and source predicate are intersected with `$and`, so a source `$or` cannot replace the recipient `$or`. Genuine suppression, reply evidence and counters still commit together; failure rolls back the new latch as well. This is target-local preservation, not a whole-workspace migration or source certification. Source classification supplies no provider-outcome evidence or execution authorization; existing original-receipt repair may finalize reporting projections while the lead stays held. No possible action is replayed.

This covers server-known, search-marked provenance. It cannot identify every historical synthetic profile or authenticate manually copied/retyped CSV/profile data after source markers are omitted. Existing CSV export is not an authenticated source certificate. Older copied records without markers need separate conservative migration/review. Manual customer-provided profile input remains legitimate intake, rather than being called verified collection.
